## 问题（2026-11-11，用户报告 + 既有证据）

现役模型在部分环境**车道线检测数量不足**。项目内既有证据：

- 远场：`lane_membership` 的远车样本实测（72 样本供货 4/72）失效三因为「不夹框心 44% /
  **缺线 35%** / 线对退化 15%」——缺线占三分之一（`maaracing_master/plugins/speedrush/lane_obs.py`
  模块 docstring，commit 历史）。
- 可用性：线观测可用率有从 45% 掉到 18%、盲窗拉到 8s 的实测案例（CODE_WIKI「线观测的绝对位
  与线锁」节的 `_assign_k` 网格接号背景）。
- **交叉依赖（新）**：深度模型选型实验正用「相邻车道线像素间距 ↔ 3.5 m」做深度米制金标
  （车道线金标探针，commit `1c82f4d`）——车道线**隔线漏检会把间距
  读成两倍、直接污染这把尺**。修召回不只是驾驶问题，也是深度标定链的数据质量问题。

算力窗口：深度模型已换装轻量替代（v5：DepthART slim-SPF，全链 38ms；MoGe 前向在
DML 上 ~40ms 固定派发税的实测见 commit `73a7164`）。深度让出 GPU 锁后，线观测
从「CPU 独立线程」上 DML 成为可选项——这改变了候选模型的算力判据，是现在做本次调研的时机。

## 生态核查（动笔前两问）

- **生态里已有什么**：MaaFW 不提供车道线观测能力；本仓已有 TwinLiteNet+（现役）与 LaneNet 系
  首眼验证（commit `07700d1`）两笔在案证据；外部生态的候选全景见下文调研（14 个模型逐一核实）。

## 调研结果（2026-11-11，两名研究员并行调研，主会话抽查复核承重数字）

### 结论速览

1. **精度口径不可直接互比**：基线家族官方只报 BDD100K 车道 IoU；CULane F1 是另一套口径。
   公平比较必须在自建游戏场景评测集上统一测。
2. **CULane 分场景表公开可查，但没有「隧道」类**（官方 9 类 = normal + crowded/night/no
   line/shadow/arrow/dazzle/curve/cross）。夜间最强公开数字是 **CLRNet 家族**
   （ResNet18 夜间 F1 75.11；论文表 1，主会话已打开原文复核）。
3. **候选几乎没有公开 x86 CPU 延迟**（论文全是 GPU/Jetson 数字）：CPU 预算只能本地实测；
   按 GFLOPs 粗算 UFLDv2/CLRNet r18 约为基线 3~5 倍算力（推定，非实测）。
4. **2025–2026 未发现「换一个更强的现成轻量模型」的捷径**：近期活跃点在 CLRNet 改进
   （CLRerNet/CLRKDNet）、视频时序车道与 3D 车道，均未在 2D 轻量分场景上显著超越上述模型。
5. **纯换现成权重（零微调）不成立**：所有候选的公开权重都训练自真车数据（CULane/BDD100K）；
   公开实证（CARLANE：无监督域适应的假阳/假阴率显著高于全监督）与本仓 LaneNet 首眼都指向
   「少量目标域标注 + 全监督微调」才是可靠路径。

## P0 分解诊断读数（2026-11-11 已跑，v2 定稿）

探针：`probe_divider_diagnosis.py`。问题：正中的白色虚线分界线肉眼清晰却几乎不产线，
到底死在哪一层？

**方法教训（自纠留档）**：v1 把「最左/最右拟合轨迹」当黄缘对去定期望分界位置——黄昏下白色
虚线常过黄色门，缘对认错后 ¼ 位置采样落在空地，读出「模型无响应」的假象。v2 缘对只认
**黄色门通过且跨度最大**的一对；响应读数改为不依赖几何假设的直接量。

**v2 读数（两模型一致）**：

1. **模型看得见虚线**：黄缘对正确的帧里，两缘之间 prob>0.30 的像素中位 **1456~2003**、
   虚线连通块中位 **3~5 个/帧**——「模型没看见」不成立。
2. **死在拟合层（主死因）**：内部轨迹几乎全死在「凑不满拟合点数」（每局 40~59 条），
   颜色门只杀 0~2 条、质量门 0 条、**接受 0 条**；未成线轨迹的整轨点数中位 = **1**、
   单带内点数中位 = **0**（拟合要求单带 ≥4 点 + 纵向跨度 ≥40px）。
   机制：**远处分界线在图像里是被透视压扁的横条，行扫描（步长 3 行）每条虚线只命中
   1~2 行**——拟合门槛为「斜率明显的连续实线」设计，虚线在结构上就不可能满足。
3. **对不对**：P1 叠图目检接受线位置贴合实际标线；P0 严格黄缘对下内部线零成线，
   不存在「检错位置」的问题——问题是「采不到」，不是「看错」。

**出路（按证据重排）**：
1. **生产拟合层按虚线形态重设计**（不动模型）→ **已落地，且比预想简单**：逐行扫描
   （步长 3→1）+ 删除颜色匹配（维护者叫停）就足够——多 dash 连通带在逐行采样下
   本就满足既有拟合门槛，无需新机制。实测同两局 48 帧（生产模型）：总成线 91→140、
   远场 59→98，道号逻辑未动，回归锁 ×2（合成虚线成线 + 颜色字段恒 "?"）。
   见 commit `cebfa34`。
2. **几何合成内部分界线**（设计候选，需方向裁决）：黄缘对 + 等宽先验在几何上已决定
   三条分界线位置，按现有双线插值同款口径从缘对合成虚拟内线，不依赖虚线成线。
3. **微调降级为次要**：能增强响应但不解决「扁横条采不到」的采样结构问题。

附带读数：**黄缘对同帧率只有 54~67%**（13~16/24）——位置原点「双侧严格可用」的上限
被黄缘对覆盖卡着，与虚线问题正交。

### 盲区点测（2026-11-11，维护者指认帧，ROI 人工划定）

维护者观察：一旦线怼在车头正下方（贴脸大虚线），模型就报不出来——假设训练集不含这种
构型。用指认帧直接量（ROI 框见 `blindspot_point.jpg`，身份先于统计量）：

| ROI（全幅坐标） | plus_small 概率 max | 原版 max |
| --- | --- | --- |
| **中心大虚线（贴脸，f0204）** | **0.0（整框零响应）** | **0.001** |
| 右前方小虚线（远，同帧） | 0.999 | 1.0 |
| 金币右侧大虚线（贴脸但偏侧，f0170） | 0.999 | 0.982 |
| 左黄线走廊（对照，f0170） | 1.0 | 1.0 |

**结论：维护者假设成立**——「压着线开、线怼在车头正下方」的构型在两个模型内部都是**纯零**，
而同帧的远处小虚线与黄线满响应。训练集是真车记录仪视角（车开在线中间），这种构型在
BDD100K/CULane 类数据里几乎不存在，属训练分布外；公开货架的车道线模型全部同源训练数据，
**换新模型解决不了这个盲区**（2025-26 扫描亦无针对此构型的工作）。「更好的模型」的产出
方式只剩**游戏帧微调自产**（P2）；远处虚线则是提取层问题，与模型无关，可先行修复。

## P2 打标可行性：虚拟机位重排骗响应（2026-11-11 首测；⚠ 当日数字系反语义所测，修正后复验仍成立，见下节）

**思路**：不改模型也不改推理——用生产标定常数（消点/地面尺度；按探针自包含约束复制，
与生产标定同源）把原帧重排成「同一地面、更远虚拟机位」的构型（pull：消点不动、横纵
按 r 同缩），贴脸正中的大虚线在重排域回到模型认识的远处形态；把重排域响应逆映射回
原帧即得盲区伪标注。地面像素严格可逆，映射不引入标注漂移。探针
`probe_warp_oracle.py`（自包含），产物 `first_look_out/warp/`（summary.md +
三联图 overlay_blind_pull_50.jpg：原生盲区框 | 重排域响应 | 逆映射伪标注）。

**读数**（帧 f0204 贴脸正中盲区，ROI 外扩框 810-960 × 520-719）：
- 原生对照：现役 max 0.028 / 原版 0.249（外扩框沾到邻线边缘；紧框即点测的 ≈0）——盲。
- pull 重排 r∈{0.25,0.35,0.5,0.7}：两模型全部 **0.999+**；vscale（只压 y）r≥0.35 亦
  0.997+，仅 r=0.25 失效——各向同性退远最稳，且温和档（0.7）就够。
- 对照帧 ×2（常规/偏侧）：重排不灭常规响应（max 恒 1.000，>0.3 像素量同量级）。

**进 P2 的口径**：打标 = 正常区域模型原生响应 ∪ 盲区重排回标（近带）；逆映射掩码在
近场按 1/r 发散变胖，**取逐行中心重画细掩码，不用原始胖掩码**；几何合成可作第二证
人，人工抽检照旧。成本：离线每帧多一次推理，生产零开销，微调完成后重排下岗。风险
如实：骗出响应 ≠ 微调必迁移，验收仍 = 原生盲区 ROI 概率抬升 + 同一质量门。

## P2 收场：微调撞墙，双通道落地后撤回（2026-11-12）

**⚠ 重排语义修正（当日最重要教训）**：cv2.warpAffine 不带 WARP_INVERSE_MAP 时把
矩阵当 src→dst 解释并内部求逆——本节首测与首版打标的「退远压缩」实际执行成「中央
放大 2 倍」。后果：首测的 0.9999 实为模型在变焦画面里看见远处路面（本来就会）；
首版标签把远带响应错投到近带行且横向错位，等于教模型压制真虚线。修正后复验：
f0204 在 pull r=0.5 下 0.9989（r=0.7 0.9953，r≤0.35 失效），对照帧不灭——思路
本身成立，仅实现曾反。

**修正标签后的微调（GPU：D:\yolo\.venv-train，torch 2.11.0+cu128；fine_tune/ 四件套：
移植/打标/训练/导出，均已入库）**：数据扩充至 763 帧（加入 1107_203433 黄昏高速
p1+p2、215421 黄昏城市、133512 白天高速；排除圈速赛与隧道）。结果：白天近场完全
拟合（0061：模型 1071px vs 标签 1053px），验证近场 IoU 0→0.60。

**撞墙（终局证据）**：黄昏贴脸构型原生视角不可学习——含 f0204 邻帧的子集死训
240 步，模型在自己带标签的训练帧上仍 0.0000，且越训越抑制；同时微调灾难性遗忘
压缩视图能力（f0204 压缩 ROI：原版 0.811→微调后 0.001）。容量/损失配比/辅助损失/
尺度增广逐变量隔离均未突破，微调路线对黄昏盲区证伪。

**双通道曾落地后撤回（b24f72c → c5c77d4，维护者目检否决）**：近带 max 融合令盲区
帧 0.0021→0.9986、48 帧成线 140→215、rms_ok 113→180，但维护者目检发现近带野线
（真线上方空沥青区两段）。诊断：野线来自压缩视图把逆光眩光带/阴影条纹误认成标线
（false_pos_source.jpg），概率级 max 融合无空间门槛全数放入；短段假线也能低残差
拟合，rms 质量门对此不敏感；打标 QA 抽样帧恰好未覆盖野线帧。

**教训**：① 压缩视图能看见真盲区，但也会把眩光/阴影看成新标线——两视图融合需要
「与原生簇去重 + 几何可信度门槛」，不是概率 max；② 目检验收必须用原始分辨率，
缩略图看不出野线；③ 可行性数字与打标同源时，验收会同时失真。微调四件套与检查点
保留备用；盲区问题回到未解状态。

## 路线判读（调研对问题的回答）

「有没有效果更好的车道线专精模型」拆成两层：

- **架构层有更强的**：CLRNet 系（夜间/遮挡公开数字最强，正对细线与断续）与 UFLDv2（混合锚正对
  远场近水平边线）在公开基准上明显强于基线同族的行锚分类法；但它们都是**线坐标族**，换架构 =
  重写概率图消费端，且 CPU 存疑、DML 依赖深度替换后的算力窗口。
- **数据层是共同前置**：两条路线都必须用游戏画面微调（零微调不成立）。本游戏的几何先验
  （四车道直道、车道线近水平直线、标定已知、帧库现成）使**几何规范化的伪标签 + 小样本全监督
  微调**成为最省人力且可核验的路径——替代公开文献里 LiDAR/外部真值的角色。
- P1/P0 补充实测（见上两节）：同族换权重几乎无差（分界线缺失与模型无关）；分界线主死因是
  生产拟合层的几何设计（扁横条虚线在行扫描+纵向拟合下结构性不可能成线），颜色门/质量门
  几乎不杀。**当下性价比最高的是拟合层按虚线形态重设计**；「从黄缘对合成内部分界线」是
  不依赖虚线的设计候选；微调降级为次要。
- 因此执行顺序是：**① 拟合层虚线化改造（设计定稿后另立实施任务）；② 几何合成方案提请
  方向裁决；③ 微调与 + Medium/Large 补测在①②之后按需评估。**「更好的模型」由实测裁决，
  不由论文数字裁决。

## 探针计划（下一步；未跑不得写成结论）

1. **P0 失效取证：已跑，读数见 P0 节。** （按 RULES 适用域：日间正常光照 × 天气随机；
   漏检已分解到层：概率层为主死因，后处理门非主因。）
2. **P1 首眼对比：已跑，读数见上节。** 后续新候选权重入 `weights/` 后同命令补测
   （探针按模型名自动识别是否带填充；新模型需自 recognizable 的 `ll` 输出头）。
3. **P2 微调自产新权重：现在有了明确目标、判据与打标方案。** 盲区点测证实「贴脸正中
   构型」是模型级盲区（换模型救不了），微调是唯一修模型的路径：伪标签 = 模型原生响应
   （正常区域）∪ 虚拟机位重排回标（盲区；可行性已验证，见上节探针）+ 人工抽检；
   单任务微调 Small（含贴脸正中构型难例），验收=同帧贴脸虚线 ROI 概率从 0 抬到可用
   + 同一质量门对比。
4. **P3 延迟实测（淘汰判据）**：P1 已给首眼数据（CPU 4 线程与 DML 双档，见上节表）；
   新候选入 `weights/` 后按同口径补测；CPU >30ms 且无 DML 窗口的候选出局。
5. **停止条件**：P0 若「缺线」集中在画面里本来没有线的段（HUD 遮挡/全遮挡），那是采样问题
   不是模型问题——先换采样再谈模型（教训：判模型失效之前先确认画面里有目标）。
