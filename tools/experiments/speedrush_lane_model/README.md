## 问题（2026-11-11，用户报告 + 既有证据）

现役模型在部分环境**车道线检测数量不足**。项目内既有证据：

- 远场：`lane_membership` 的远车样本实测（72 样本供货 4/72）失效三因为「不夹框心 44% /
  **缺线 35%** / 线对退化 15%」——缺线占三分之一（`maaracing_master/plugins/speedrush/lane_obs.py`
  模块 docstring，commit 历史）。
- 可用性：线观测可用率有从 45% 掉到 18%、盲窗拉到 8s 的实测案例（CODE_WIKI「线观测的绝对位
  与线锁」节的 `_assign_k` 网格接号背景）。
- **交叉依赖（新）**：深度模型选型实验正用「相邻车道线像素间距 ↔ 3.5 m」做深度米制金标
  （车道线金标探针，commit `1c82f4d`）——车道线**隔线漏检会把间距
  读成两倍、直接污染这把尺**。修召回不只是驾驶问题，也是深度标定链的数据质量问题。

算力窗口：深度模型已换装轻量替代（v5：DepthART slim-SPF，全链 38ms；MoGe 前向在
DML 上 ~40ms 固定派发税的实测见 commit `73a7164`）。深度让出 GPU 锁后，线观测
从「CPU 独立线程」上 DML 成为可选项——这改变了候选模型的算力判据，是现在做本次调研的时机。

- **生态里已有什么**：MaaFW 不提供车道线观测能力；本仓已有 TwinLiteNet+（现役）与 LaneNet 系

## 调研结果（2026-11-11，两名研究员并行调研，主会话抽查复核承重数字）

### 结论速览

1. **精度口径不可直接互比**：基线家族官方只报 BDD100K 车道 IoU；CULane F1 是另一套口径。
   公平比较必须在自建游戏场景评测集上统一测。
2. **CULane 分场景表公开可查，但没有「隧道」类**（官方 9 类 = normal + crowded/night/no
   line/shadow/arrow/dazzle/curve/cross）。夜间最强公开数字是 **CLRNet 家族**
   （ResNet18 夜间 F1 75.11；论文表 1，主会话已打开原文复核）。
3. **候选几乎没有公开 x86 CPU 延迟**（论文全是 GPU/Jetson 数字）：CPU 预算只能本地实测；
   按 GFLOPs 粗算 UFLDv2/CLRNet r18 约为基线 3~5 倍算力（推定，非实测）。
4. **2025–2026 未发现「换一个更强的现成轻量模型」的捷径**：近期活跃点在 CLRNet 改进
   （CLRerNet/CLRKDNet）、视频时序车道与 3D 车道，均未在 2D 轻量分场景上显著超越上述模型。
5. **纯换现成权重（零微调）不成立**：所有候选的公开权重都训练自真车数据（CULane/BDD100K）；
   公开实证（CARLANE：无监督域适应的假阳/假阴率显著高于全监督）与本仓 LaneNet 首眼都指向
   「少量目标域标注 + 全监督微调」才是可靠路径。

## P0 分解诊断读数（2026-11-11 已跑，v2 定稿）

探针：`probe_divider_diagnosis.py`。问题：正中的白色虚线分界线肉眼清晰却几乎不产线，
到底死在哪一层？

**方法教训（自纠留档）**：v1 把「最左/最右拟合轨迹」当黄缘对去定期望分界位置——黄昏下白色
虚线常过黄色门，缘对认错后 ¼ 位置采样落在空地，读出「模型无响应」的假象。v2 缘对只认
**黄色门通过且跨度最大**的一对；响应读数改为不依赖几何假设的直接量。

**v2 读数（两模型一致）**：

1. **模型看得见虚线**：黄缘对正确的帧里，两缘之间 prob>0.30 的像素中位 **1456~2003**、
   虚线连通块中位 **3~5 个/帧**——「模型没看见」不成立。
2. **死在拟合层（主死因）**：内部轨迹几乎全死在「凑不满拟合点数」（每局 40~59 条），
   颜色门只杀 0~2 条、质量门 0 条、**接受 0 条**；未成线轨迹的整轨点数中位 = **1**、
   单带内点数中位 = **0**（拟合要求单带 ≥4 点 + 纵向跨度 ≥40px）。
   机制：**远处分界线在图像里是被透视压扁的横条，行扫描（步长 3 行）每条虚线只命中
   1~2 行**——拟合门槛为「斜率明显的连续实线」设计，虚线在结构上就不可能满足。
3. **对不对**：P1 叠图目检接受线位置贴合实际标线；P0 严格黄缘对下内部线零成线，
   不存在「检错位置」的问题——问题是「采不到」，不是「看错」。

**出路（按证据重排）**：
1. **生产拟合层按虚线形态重设计**（不动模型）→ **已落地，且比预想简单**：逐行扫描
   （步长 3→1）+ 删除颜色匹配（维护者叫停）就足够——多 dash 连通带在逐行采样下
   本就满足既有拟合门槛，无需新机制。实测同两局 48 帧（生产模型）：总成线 91→140、
   远场 59→98，道号逻辑未动，回归锁 ×2（合成虚线成线 + 颜色字段恒 "?"）。
   见 commit `cebfa34`。
2. **几何合成内部分界线**（设计候选，需方向裁决）：黄缘对 + 等宽先验在几何上已决定
   三条分界线位置，按现有双线插值同款口径从缘对合成虚拟内线，不依赖虚线成线。
3. **微调降级为次要**：能增强响应但不解决「扁横条采不到」的采样结构问题。

附带读数：**黄缘对同帧率只有 54~67%**（13~16/24）——位置原点「双侧严格可用」的上限
被黄缘对覆盖卡着，与虚线问题正交。

### 盲区点测（2026-11-11，维护者指认帧，ROI 人工划定）

维护者观察：一旦线怼在车头正下方（贴脸大虚线），模型就报不出来——假设训练集不含这种
构型。用指认帧直接量（ROI 框见 `blindspot_point.jpg`，身份先于统计量）：

| ROI（全幅坐标） | plus_small 概率 max | 原版 max |
| --- | --- | --- |
| **中心大虚线（贴脸，f0204）** | **0.0（整框零响应）** | **0.001** |
| 右前方小虚线（远，同帧） | 0.999 | 1.0 |
| 金币右侧大虚线（贴脸但偏侧，f0170） | 0.999 | 0.982 |
| 左黄线走廊（对照，f0170） | 1.0 | 1.0 |

**结论：维护者假设成立**——「压着线开、线怼在车头正下方」的构型在两个模型内部都是**纯零**，
而同帧的远处小虚线与黄线满响应。训练集是真车记录仪视角（车开在线中间），这种构型在
BDD100K/CULane 类数据里几乎不存在，属训练分布外；公开货架的车道线模型全部同源训练数据，
**换新模型解决不了这个盲区**（2025-26 扫描亦无针对此构型的工作）。「更好的模型」的产出
方式只剩**游戏帧微调自产**（P2）；远处虚线则是提取层问题，与模型无关，可先行修复。

## P2 打标可行性：虚拟机位重排骗响应（2026-11-11 首测；⚠ 当日数字系反语义所测，修正后复验仍成立，见下节）

**思路**：不改模型也不改推理——用生产标定常数（消点/地面尺度；按探针自包含约束复制，
与生产标定同源）把原帧重排成「同一地面、更远虚拟机位」的构型（pull：消点不动、横纵
按 r 同缩），贴脸正中的大虚线在重排域回到模型认识的远处形态；把重排域响应逆映射回
原帧即得盲区伪标注。地面像素严格可逆，映射不引入标注漂移。探针
`probe_warp_oracle.py`（自包含），产物 `first_look_out/warp/`（summary.md +
三联图 overlay_blind_pull_50.jpg：原生盲区框 | 重排域响应 | 逆映射伪标注）。

**读数**（帧 f0204 贴脸正中盲区，ROI 外扩框 810-960 × 520-719）：
- 原生对照：现役 max 0.028 / 原版 0.249（外扩框沾到邻线边缘；紧框即点测的 ≈0）——盲。
- pull 重排 r∈{0.25,0.35,0.5,0.7}：两模型全部 **0.999+**；vscale（只压 y）r≥0.35 亦
  0.997+，仅 r=0.25 失效——各向同性退远最稳，且温和档（0.7）就够。
- 对照帧 ×2（常规/偏侧）：重排不灭常规响应（max 恒 1.000，>0.3 像素量同量级）。

**进 P2 的口径**：打标 = 正常区域模型原生响应 ∪ 盲区重排回标（近带）；逆映射掩码在
近场按 1/r 发散变胖，**取逐行中心重画细掩码，不用原始胖掩码**；几何合成可作第二证
人，人工抽检照旧。成本：离线每帧多一次推理，生产零开销，微调完成后重排下岗。风险
如实：骗出响应 ≠ 微调必迁移，验收仍 = 原生盲区 ROI 概率抬升 + 同一质量门。

## P2 收场：微调撞墙，双通道落地后撤回（2026-11-12）

**⚠ 重排语义修正（当日最重要教训）**：cv2.warpAffine 不带 WARP_INVERSE_MAP 时把
矩阵当 src→dst 解释并内部求逆——本节首测与首版打标的「退远压缩」实际执行成「中央
放大 2 倍」。后果：首测的 0.9999 实为模型在变焦画面里看见远处路面（本来就会）；
首版标签把远带响应错投到近带行且横向错位，等于教模型压制真虚线。修正后复验：
f0204 在 pull r=0.5 下 0.9989（r=0.7 0.9953，r≤0.35 失效），对照帧不灭——思路
本身成立，仅实现曾反。

**修正标签后的微调（GPU 训练环境：torch 2.11.0+cu128；fine_tune/ 四件套：
移植/打标/训练/导出，均已入库）**：数据扩充至 763 帧（加入 1107_203433 黄昏高速
p1+p2、215421 黄昏城市、133512 白天高速；排除圈速赛与隧道）。结果：白天近场完全
拟合（0061：模型 1071px vs 标签 1053px），验证近场 IoU 0→0.60。

**撞墙（终局证据）**：黄昏贴脸构型原生视角不可学习——含 f0204 邻帧的子集死训
240 步，模型在自己带标签的训练帧上仍 0.0000，且越训越抑制；同时微调灾难性遗忘
压缩视图能力（f0204 压缩 ROI：原版 0.811→微调后 0.001）。容量/损失配比/辅助损失/
尺度增广逐变量隔离均未突破，微调路线对黄昏盲区证伪。

**双通道曾落地后撤回（b24f72c → c5c77d4，维护者目检否决）**：近带 max 融合令盲区
帧 0.0021→0.9986、48 帧成线 140→215、rms_ok 113→180，但维护者目检发现近带野线
（真线上方空沥青区两段）。诊断：野线来自压缩视图把逆光眩光带/阴影条纹误认成标线

拟合，rms 质量门对此不敏感；打标 QA 抽样帧恰好未覆盖野线帧。

**教训**：① 压缩视图能看见真盲区，但也会把眩光/阴影看成新标线——两视图融合需要
「与原生簇去重 + 几何可信度门槛」，不是概率 max；② 目检验收必须用原始分辨率，
缩略图看不出野线；③ 可行性数字与打标同源时，验收会同时失真。微调四件套与检查点
保留备用；盲区问题回到未解状态。

**⚠ 2026-11-12 训练集审计后状态更正**：本节「微调路线对黄昏盲区证伪」所依赖的

## 推理侧局部重映射复核（2026-11-12，维护者提案）

提案：不重训、不优化指标、不整图匹配对比，只把「车头 / 引擎盖区」重映射到别处，看
现役模型能否检出被压住的标线。**结论：该路线不成立**，且顺带查出旧证据链的地基错误。

**目标定位纠错（最重要）**：维护者指认帧 f0204 属会话 `20261109_104823_manual_p2`。
旧点测框（全幅 830-935 × 530-718）内**是空沥青、本来就没有线**，其零响应是正确输出；
真正的盲线由逐列高亮峰定位在内容域 x 258-282 / y 265-360（全幅 516-564 × 530-720），
原生 max 0.0028。旧重排探针的帧根写的是 `..._manual_p1`，读的是**另一帧**——
「虚拟机位重排 r=0.5 骗出 0.9989」是在错帧加错框上得到的。用正确帧与目标线复核
pull r∈{1.0,0.7,0.5,0.35}：目标线 max 依次 0.0028 / 0.0315 / 0.0055 / 0.0013，
全档零个 >0.3 像素；同帧右侧斜白线各档恒 0.99+。**整图退远重排对目标线无效**，
P2 打标、微调、双通道三条后续结论的地基均不成立。

**三组假设族逐一证伪**（探针 `probe_local_remap.py`、`probe_local_reshape.py`，读数在
`first_look_out/remap/`）：

1. **位置**：把含目标线的 160×120 块平移到右侧近场 / 中带 / 远带 / 左上，max 全在
   0.0001~0.0044；反向把右侧已检出的斜线搬进车头区仍 0.9989（573 个 >0.3 像素）；
   近带整带上移 60/100/140 行全盲。位置不是主因。
2. **线形与尺度**：对同块做横向压缩（0.25~0.6）、斜切（±0.2 / 0.4）、纵向压缩、
   等比缩小，原位全盲；搬到远带出现的零星高分（最多 3 个 >0.3 像素）与「抹掉白线」
   的空白对照同量级（约 0.46），是块接缝假响应，不是检出。
3. **全局上下文**：把该块单独成图（灰底 / 放大成整幅）、或把画面其他车道线与远场线族
   抹掉，目标线仍为 0；且上下文一破模型全图输出整体归零，说明它强依赖全局道路结构。

**判读**：现役模型对这条「近场、竖直、粗、连续」的白条，不存在可借输入几何绕过的
响应路径——它内部的车道线判据就不把这种形态当线。要让它认，只能改权重（针对该构型
给最小正例，不追泛化指标），或改由几何补线绕开模型；两者都是新方向，待裁决。
首版 `probe_local_remap.py` 曾把车头区块定偏（未覆盖目标线），其读数已作废，现文件
为按逐列高亮峰纠正后的版本。

**补充：连续非线性「弯」与伪造车头盖（2026-11-12，维护者追问）**：维护者提出不改
权重、只跑一次推理，把画面底部沿拱形「弯」出一个人造车头盖（模型在真车数据里习惯
底部中央是引擎盖），并把被盖住的近场内容压到盖子上方的可见区。探针
`probe_bend_hood.py` 在另一帧（0202，贴脸粗白线内容域 x310-339 / y253-360，原生
max 0.0006）上做连续无接缝重映射：拱盖遮罩、纵向非线性压缩（拱顶 210 / 245 / 280）、
沿地面射线同步压窄，以及抹掉白线的空白对照。全部变体目标区 max ≤ 0.0202、>0.3
像素恒 0；温和档（拱顶 280）全图响应 3353（原生 2819）、左右黄线与斜白线照常检出，
唯独中央那条线仍为零；剧烈档（拱顶 210）连全图响应都归零。目标标记随同一映射落在
y206~279（564~1740 像素），身份核对无误。「只加遮罩」变体把整条线挖掉（标记 0
像素），其零读数不作证据。至此输入侧的平移、线性仿射、局部块变形、连续非线性弯曲、
伪造车头盖全部证伪：模型拒绝这条线不是构图或位置问题，而是权重内部的车道线类别
判据——与「给定正例微调即可学会」互证。

**性能口径更正**：上一节结尾把「消费端加硬几何门」表述成需要两次推理的融合，这是
错的。换成微调权重本身就是**单模型、单次推理、零额外开销**；野线是输出层的假阳性，
由生产提取层既有的等间距 / 残差 / 线角几何门过滤即可，不需要第二个模型。维护者
明确不接受两次推理，故后续不得再提融合方案。

## 定向微调重审（2026-11-12，维护者裁定「最小正例」）

前述「微调对贴脸盲区证伪」作废：它建立在标签里根本没有目标线的前提下。本轮按
「用几何直接给这条线的正例、只针对该构型、不追指标」重审。结论：**教得会**，
但**直接换权重不能上生产**。本节取代前节「须以金标准集重审」的待办表述。

- **标签**（`fine_tune/make_target_labels.py`）：不来自任何模型输出。用 61 列大窗口
  局部亮度差（白线比沥青亮 36~47 级）抠出近场中央那条粗白虚线，连通域按细长 /
  伸到画面底部 / 落在近场中央筛选，再按行中心重画细掩码。黄昏下该线偏米黄
  （饱和度中位约 124），按「白色低饱和」筛会正好把它漏掉。8 会话扫出 56 帧，
  拼图目检后质量闸留 23 帧，留出 f0204 不训。
- **训练**（`fine_tune/train_targeted.py`）：只解冻车道头三层；目标区推正例，
  其余区域用现役模型原生概率做蒸馏保持（防灾难性遗忘），背景区加抑制。
  首版用分类损失时正例项约 10、保持项约 0.01，十步就把其他线全训没了；两项
  同改 MSE 后量级才平衡。另加 47 张「纯保持帧」（无目标构型、只把输出拉回现役）。
- **结果**（step 80，`weights/plus_small_targeted_v2_384x640.onnx`，导出对齐
  2.6e-05）：f0204 目标线 0.0028 / 0 像素 → **0.9948 / 438 像素**；同帧右侧斜线
  0.9993 / 672 → 0.9999 / 676（无损），黄线仍在。f0210 / f0300 / f0500 上目标线
  同样从约 0 抬到 0.90~0.99。**「这个构型学不会」被证伪**，上一代理的失败是标签
  没教，不是容量或域差。
- **否决点**（原始分辨率目检，见 `probe_verify_targeted.py` 差分图）：目标框外
  新增响应 4900~8600 像素/帧，落在天空云层、左右车道空沥青与护栏上；f0500
  左车道出现大片糊斑。全图 >0.3 像素由约 4300 涨到 9400~13300，黄线区涨 2~5 倍。
  损失平衡、加权保持、背景抑制、纯保持帧四种做法都没压住，按「未收敛换假设、
  不加码参数」停止。与双通道被否的野线属同一族失败模式。

**落地判读**：目标 ROI 内的输出是对的，野线全在 ROI 外。不必再改模型，只需在
消费端加**硬几何门**——只在已知贴脸盲区带内取该权重输出、其余一律用现役模型，
并与原生线簇去重；这正对应「融合要带空间门槛，不是概率 max」的既有教训。
是否按此接入生产属新方向，待维护者裁决；当前不动生产代码。

| 软概率直接交叉熵 | 0.47 / 16px | 0.078 / 0px | 9147 | 38 |
| 硬标签 + 逐行中心细化 | 0.71 / 113px | 0.395 / 11px | 10486 | 157 |

**根因判读（有对照图证据）**：教师软标签本身干净，但学生忠实学会了教师
「把线标粗、标全」的风格——黄线像素 1144 → 3000~6000、全图响应 4480 →
1~2 万。原始分辨率目检（`verify_*_f0500.jpg`）显示线宽放大 3~4 倍、
右侧分界线连成糊带；这不是上次那种「位置错误的野线」，但同样破坏生产
行扫描与等宽先验。`teacher_label_audit.jpg` 证明逐行中心细化还会额外造出
多条平行假线，故该口径亦不可沿用。f0202 属训练集中不存在的会话（域外帧），
三版都泛化失败（目标线最高 0.395）。

### 失败归因（2026-11-12 追加，维护者两问）

维护者追问「蒸馏为什么失败」与「教师是不是在描边、小模型画的是线体」。
两个问题都查实了，且第二个是主因。

**（1）教师实测在「描边」，不是画线体。** 全量剖面机检（120 帧 × 每 6 行）：
每行段数中位 4、p90 6；**相邻段间距落在 2~25px 的占全部段对的 42.7%，
中位间距 8px**——即同一条线的左右边缘各出一条细带，中间是线体。放大 6 倍
目检（`fine_tune_out/teacher_labels/stroke_zoom.jpg`）确认：绿标只压在
车道线左边缘，米白色线体基本未被覆盖。这直接解释了 `hard` 口径为何造出
平行假线——一行内两个边缘段各取中心，必然得到两条线。
另注：该教师 HF 仓 model card 为空、月下载 28 次，属**未经他人验证的社区
权重**，其「描边」风格很可能是训练数据标注口径所致，不是通用 SOTA 行为。

**（2）修描边：合并填实（`fill` 口径）。** 同行间距 ≤25px 的相邻段合并、
整段填实为线体，宽度 >60px 视为糊带丢弃。实测 80 帧平均正例 7775→8704 像素，
放大对照见 `fill_compare.jpg`。但**只能部分还原**：教师在这条线上往往只标
了单侧边缘，另一侧本来就缺失，合并补不出来（还会产生水平短条伪影）。

**（3）文献侧的失败机制**（与本次现象逐条对上）：
- **容量差距**：教师 27.3M 参数 → 学生约 0.5M，比例远超经验建议的
  10%~30%，小模型拟合不了教师的复杂软分布
  （[CSDN 2025-12 容量匹配](https://blog.csdn.net/GatherTide/article/details/155876264)、
  [百度云 2025-09](https://cloud.baidu.com/article/3772211)）。
- **结构不相似**：Transformer 教师（SegFormer）蒸馏 CNN 学生，效果显著差于
  同族蒸馏（同上）。
- **密集预测正负样本极不平衡**：分割/检测类蒸馏不能直接套分类蒸馏，
  需任务特定策略
  （[知乎 2026-07](https://zhuanlan.zhihu.com/p/2060707105284290223)）。
- 教师软概率**未校准到目标域**（全图 max 0.84、仅 3.4% 像素 >0.30），
  直接做软目标会把学生教成「处处 0.4」。

**（4）`fill` 口径实测（第五版）**：f0204 目标线 **0.964 / 180 像素**、
f0202 0.528 / 45 像素，回归线全在 0.99+，是三版里目标线最好的；但全图
响应 4480 → 1.7~1.9 万、f0202 天空 383 像素，原始分辨率目检左黄线整片
糊成绿带（`verify_fill_f0204.jpg`）。**仍不通过「无野线」验收。**

**结论**：维护者的路线在「教师能看见」这一环成立，但**教师质量（描边、
单侧边缘、未校准、来源未经他人验证）与容量/结构不匹配共同导致蒸馏失败**。
五种标签口径（软 CE / 硬+细化 / 标度校准 / 二值 / 合并填实）全部收敛到
「线变粗成糊带 + 域外帧野线」。不追指标、不上生产、生产代码未改动。

### 换 SCNN 分割族当教师（2026-11-12 追加，维护者裁定「先调查」）

上节把下一步指向「换一个画线体、区域分割、有评测背书的教师」。
按此调查 **UnLanedet 的 SCNN（ResNet18 / TuSimple）**：权重 91MB 从官方
Release 直链可下，结构自包含复现（ResNet18 膨胀 + 四方向 SCNN 聚合 +
1×1 解码到 7 类），权重 **127/127 全匹配**。探针 `probe_teacher_scnn.py`。

**预处理踩坑（后续跑 UnLanedet 系必用）**：config 写
`mean=[103.939,116.779,123.68], std=[1,1,1]`，但实测**必须先 `/255`
再减 `mean/255`**；直接减 0–255 量级的均值会让 logits 爆到 ±500、
softmax 全判背景（前景像素 0 vs 15694）。四种口径逐一试过才定位。

**读数**：

| 帧 | 目标贴脸线 | 右侧线 | 黄线 | 天空 |
|---|---|---|---|---|
| f0204 | **0.0 / 0 像素** | 0.933 / 905 | 0.995 / 1219 | **0.992 / 5717** |
| f0202 | **0.0 / 0 像素** | 0.913 / 46 | 0.800 / 1450 | **0.997 / 5236** |
| f0500 | — | 0.006 / 0 | 0.999 / 2498 | **0.996 / 9694** |

原始分辨率目检（`first_look_out/teacher_scnn/f0204_scnn.jpg`）：红框内
**无任何响应**；天空云层被标成大片绿斑；左右车道线被画成横跨画面的
巨大三角斜线——域差远大于 SegFormer。**不可用作训练标签。**

**结论（这条支路关闭）**：真车数据训练的分割族（TuSimple/CULane）在游戏
帧上同样看不见贴脸构型，且域差导致天空误检与跨画面斜线。「换教师」的两种
口径至此都已实测：

- 通用大分割（SegFormer 社区权重）：**看得见**，但描边、单侧边缘、概率未校准；
- 专业车道线分割（SCNN/TuSimple）：**看不见**，域差更大。

RESA 与 SCNN 同数据集同标注口径、权重已下（106MB）但未跑，预期相同；
若继续验证，判据同本节（目标 ROI 是否非零 + 天空误检）。**这说明贴脸构型
不是「换个更强的现成模型就能标注」的问题，而是所有真车数据训练的车道线
模型都不含该构型的监督**。可走的路只剩两条：① 自己用几何/亮度真值造
正例（已证能教会，野线未解决）；② 绕开模型由几何直接补线。两者都需裁决。

## SAM 标注 + 专项中心学习（2026-11-12，维护者提案）

维护者提案：「叫分割甚至语义模型来标注，专项做中心位置的车道线学习」。
拆成两半分别实测：**标注成了，训练卡在单模型架构**。

### 一、SAM 标注：成立，而且是目前最好的标签

**为什么换 SAM**：车道线专精模型都带「真车底部没有车道线」的类别先验
（SegFormer 描边、SCNN 看不见），而 SAM 是**类别无关**的通用分割——给一个
框就把框内物体抠出来，不知道也不关心「这是不是车道线」。

**做法**（`probe_teacher_sam.py` / `fine_tune/make_sam_labels.py`）：提示框来自
已有的亮度几何真值 bbox（真值只给位置，掩码边界由 SAM 出）。权重
`facebook/sam-vit-base`（375MB，HF 经代理可下；首次下载被截断需校验体积）。

**结果**：f0204 掩码 1746 px vs 几何真值 1734 px、f0202 1904 vs 1945——
面积几乎一致但**形态完全不同**：原始分辨率放大目检确认 SAM 覆盖整条白线的
**整个宽度（线体）**，几何真值只覆盖左半。56 帧批量标注 24 秒，质量闸留
49 帧（剔除位置偏左 x<180 或面积比异常）。目检 12 帧拼图：青色均贴合线体，
无溢到沥青/护栏。

### 二、专项中心学习：四次训练全部失败

| 版本 | 结构 | 目标线最好 | 天空野线 | 回归线 |
|---|---|---|---|---|
| `train_center_specialist.py` | 只在中心 ROI 算损失 | 0.40 / 154px | 672 | 第 10 步全图归零 |
| 同上 + 负例帧 60 | 中心 ROI 正负例 | 0.47 / 419px | 797 | 同上 |
| `train_sam_center.py` | 中心 SAM + 外围现役保持 | 0.54 / 730px | 681 | 外围仍被带坏 |
| 同上、去掉负例帧 | 中心正例 + 外围保持 | 0.54 / 1131px | 488 | 同上 |

**失败机制（有读数支撑）**：
1. **只算 ROI 损失挡不住参数共享**：负例帧把模型先压成「处处不输出」
   （第 10 步全图响应 0），随后为在中心出线又把天空点着。
2. **目标线概率上不去**：始终停在 0.47~0.54，而之前用亮度细标签的
   `train_targeted` 能到 0.99。SAM 线体掩码更宽更完整，在冻结 backbone +
   只解冻车道头的容量下拟合不到高置信。
3. **外围保持项压不住**：保持项 0.012 对中心项 0.18，量级差 15 倍。

**架构层判断**：单模型、单次推理、冻结 backbone、只调车道头——要同时做到
「中心学会新构型 + 外围完全不变 + 无野线」，在这套约束下做不到。这不是
标签或损失设计的问题：四次换法都收敛到同一模式。

### 三、标签纠错：维护者目检抓出 40% 误标（关键转折）

维护者指出拼图里有几格标的不是车道线。实测坐实：**大量帧的掩码尺寸完全一致
（宽 24~26、高 35~36、底边停在 y≈333）**——是画面底部中央一个固定小物体被
几何真值的错框框住后由 SAM 抠出。真正的贴脸线一定延伸到画面底部、高度 60+。
另有一类误标是框到**车身/警车**（掩码内亮度不比沥青高）和**糊片**（面积 7024）。

修正后的质量闸（四道，缺一不可）：高度 ≥60、面积 900~3600、
高宽比 ≥1.15、**掩码内亮度比周围沥青高 ≥18**、底边 ≥300。
56 帧 → **20 帧**（宁缺毋滥），原始分辨率目检 12 格全部压在车道线上。

**这一修直接翻案**：用干净标签重训，目标线立刻学会——
f0204 **0.0028 → 0.89 / 944 像素**、f0202 **0.0006 → 0.94 / 1567 像素**。
前四次失败的**主因就是那 40% 错标签**，模型在学「底部有个小圆点」。

### 四、C 方案（靠生产几何门过滤野线）实测失败

先按生产口径分区统计：天空野线（y<165，1277/2601/1505 像素）**不在生产行
扫描范围（y 206~359）内**，远场几乎不变；生产扫描区增加 40~80%。看似可行。

但跑生产同口径线提取（`probe_gate_filter.py` 复用 `probe_first_look.py` 的
行扫描→轨迹→拟合→颜色/残差/线角门）后：

| 标签形态 | 目标线概率 | 能拟合的轨迹 | 残差 rms（门槛 3.0） | 门后结果 |
|---|---|---|---|---|
| SAM 线体（不细化） | 0.89 / 0.94 | 2 条 | **5.1 / 3.8** | 全被残差门滤掉，f0204 剩 0 条线 |
| 逐行细化 5px | 0.54 / 0.54 | 3 条 | 1.05 通过但位置在 x 7~231 | 目标线 x≈270 处轨迹断裂，未捕获 |

**两难**：线体标签让输出线变粗、质心抖动、残差超门被全部滤掉；细化标签让
信号变弱（0.54）、行扫描在目标位置连不成轨迹（诊断显示 x 231~503 区间为空）。

**结论**：生产的几何门与现役模型的输出形态强绑定（残差 3.0 是按细线调的）。
任何改变输出形态的微调都会失配——不是「门滤不干净」，是「门把真线也滤了」。
**C 方案不可行**，除非改生产提取层的门槛参数（属新方向，需裁决）。

### 五、负训练与上下文实验（2026-11-12，维护者三问）

维护者三点：① 应有负训练，把误检图像当惩罚喂回去；② 生产有路面平面拟合，
不怕路面外的误标；③ 模型是否靠天空建立上下文。逐条实测：

**（1）上下文：不靠天空，靠中远场车道线的透视结构。**

| 涂灰范围 | 现役模型 | 新模型 |
|---|---|---|
| 只涂天空+远景 y<165 | 右侧线 0.999→1.0，几乎不变 | 目标线 0.89→0.886 |
| 连中远场车道线 y<206 | **全部归零** | **全部归零** |
| 只留中央竖带 | 归零 | 目标线仍有 0.871 |

天空完全不参与判断；中远场车道线一涂掉模型就瞎。**训练时天空可不管**
（正合「生产有平面拟合」），中远场必须重点保护。

**（2）负训练有效，但目标线信号被压。** 按区域加权（天空 0、中远场 3.0、
近场 1.0），负例优先选「上一版权重在中心 ROI 确实误检」的帧（80 帧误检 +
2 帧兜底，共 102 帧）：

| 指标 | 无负例（线体版） | 加负例 + 区域加权 |
|---|---|---|
| f0204 目标线 | 0.89 / 944px | 0.40 / 14px |
| 天空野线 f0204 | 1277 | **357** |
| 全图 >0.3 f0204 | 6731 | **5091** |
| 回归线 | 破 | **保住** |

野线大幅下降、回归线保住，但目标线信号从 0.89 掉到 0.40——正负样本权衡。

**（3）真正的根因：输出是散点，不是连续线。** 逐行检查目标区概率：

| y | 270 | 290 | 310 | 330 | 350 |
|---|---|---|---|---|---|
| prob max | 0.005 | 0.070 | 0.003 | 0.069 | 0.463 |

「0.89 / 944 像素」是**区域内最大值 + 过阈像素总数**，听起来像学会了，实际是
**零散点亮的散点**，不是一条连续的线。生产的行扫描要求每行有明确的连续段，
散点连不成轨迹（`probe_gate_filter.py` 显示目标 x 区间轨迹为空），残差自然超门。

**结论**：单模型微调这条路已到终点——不是「学不会」，而是**在冻结主干、只调
车道头的容量下，模型只能学出「这片区域大概有线」的模糊散点，学不出「每行
一个明确位置」的连续细线**。生产的整条提取链（行扫描→轨迹→拟合→残差门）
都建立在这个前提上。

**可选出路（需维护者裁决）**：
- **A. 极轻量中心分支**：并联一个小网络只吃中心 ROI 裁剪块（如 270×120），
  开销预计 <1ms（主模型 23ms）。最贴合「专项中心学习」的字面意思，但严格说
  是额外一次小推理。
- **B. 解冻 backbone 更多层**：容量上去了，破坏外围的风险同步变大。
- **C. 接受 0.5 概率 + 生产几何门**：已过 0.30 阈值，靠既有等距/残差/线角门
  过滤野线；需先验证几何门能否滤净。
- **D. 放弃模型，几何直接补线**。

## 论文口径重训：损失函数是散点的真因（2026-11-12，维护者「查论文」提案）

**问题**：中心专项训练后目标线概率能到 0.89，但逐行检查是散点
（f0204 目标区逐行 max = 0.005 / 0.070 / 0.003 / 0.069 / 0.463），
生产行扫描连不成轨迹。此前归因为「冻结主干容量不够」。

**论文口径**（TwinLiteNet+，[arXiv:2403.16958 v6](https://arxiv.org/abs/2403.16958)）：
- 两个分割分支**各自**用 **Focal(γ=2, α=0.25) + Tversky(α=0.9, β=0.1)**；
  车道分支 α>β 刻意偏重召回。不是 BCE/CE。
- AdamW，lr 5e-4，wd 5e-4，bs 16，100 epochs，输入 640×384，
  光度（HSV）+ 几何（平移/裁剪/水平翻转）增强，EMA 推理。
- 结构：ESP 编码器（Stride ESP + Depthwise ESP 空洞卷积 + HFF）→
  **PCAA**（局部类激活图引导的通道注意力）→ 两支独立解码器
  UCB→UCB→USB（转置卷积 + 与输入低分辨率图 concat）。
- BDD100K 上车道 IoU 仅 **34.2%**（可行驶区 92.9% mIoU）——细线类不平衡，
  这个模型的车道头本来就是弱项。

**机制判读**：逐像素 BCE 对散点是**合法最优解**（每行点亮几个点损失就降下去）；
Tversky 是区域级重叠（TP/FN/FP 集合量），散点会推高 FN，因此天然逼模型覆盖
连续线体。这就是「0.89 但提取不到」的根因，不是容量问题。

**实测**（`fine_tune/train_paper_loss.py`，ROI 内 Focal+Tversky，外围仍用
现役原生概率做自适应权重保持，`lam` 自动配平量级）：

| 配置 | f0204 行覆盖 / 抖动 | f0202 行覆盖 / 抖动 | 生产几何门（目标是否被覆盖） |
|---|---|---|---|
| 现役 | 0.0 / — | 0.0 / — | — |
| BCE 散点版（旧） | 逐行 0.003~0.463，无连续段 | 同 | 否 |
| Focal+Tversky，解冻 PCAA，1200 步 | 0.842 / 8.94 | 0.972 / 3.24 | **f0204 ✅ / f0202 ✅** |
| Focal+Tversky，**不解冻 PCAA**，800 步 | 0.842 / 7.97 | 0.953 / 3.45 | **f0204 ✅ / f0202 ✅** |

生产同口径线提取（`probe_gate_filter.py`）给出的新增线：
- f0204：`(271, 276, 'near', 'y')` —— 就是那条贴脸粗白虚线
- f0202：`(322, 330, 'near', 'y')` —— 同上
- 原有黄线、右侧斜白线位置不变，线数 3→3（没有多出野线）

**消融结论**：解冻 PCAA **不是必需的**——只换损失、只训 3.8K 参数（vs 12.8K）
同样过门，且天空响应更少（2208 vs 4105 像素）。论文里 PCAA 是精度模块，
但本任务的瓶颈在损失形态，不在注意力容量。

**必须记录的口径纠错**：`probe_first_look.py` 此前把 **RGB** 传给模型，
而生产 `lane_obs.py:137` 是 `cv2.imread` 的 **BGR** 直喂。现役模型对通道不
敏感（目标区 0.002 vs 0.003），但微调权重会差到 **0.116 vs 1.0**，导致
「C 方案：几何门把真线一起滤掉」的结论**完全反向**。已把 `lane_prob` /
`extract_lines` / `render_thumb` / `probe_gate_filter` 统一为 BGR，并在此
更正：**几何门并不排斥这条线，此前是探针喂错了通道。**

**天空野线的判读**：本版天空（y<165）仍有 2208~4105 个响应像素，但生产行
扫描带是内容域 y 206~360，且地平线以上几何弃权（`lane_obs.py` 灭点门），
路面外响应不进消费端——与维护者「生产有路面平面拟合，不怕路面外误标」一致。
近带（y 265~360）内未见新增野线；红框右侧那个底部小图标会被点亮，但没有
形成可拟合的轨迹（几何门后线数未增加）。

**产物**：`plus_small_paperloss2_384x640.onnx`（解冻 PCAA，1200 步）、
`plus_small_paperloss_nopcaa_384x640.onnx`（推荐：改动最小、同样过门），
均未接生产。权重在实验目录，生产代码未动。

### 消费端剔除方案（`probe_hud_gate.py`，已验证）

维护者指出「徽章里的头像是随机的」，所以整图模板匹配不可用。实际做法分两步：

**第一步：定位徽章（与头像无关）。** 徽章由红环 + 随机头像 + 下方白字「XX米」组成，
只有「米」字是固定字体、固定位置渲染的。实测：

| 判据 | 含徽章帧 | 不含徽章帧 |
|---|---|---|
| 「米」字模板匹配得分 | 0.74–1.00 | 0.38–0.47 |
| 「米」字纵坐标 | 恒为 y=641（720 高的 0.890） | — |

所以用「米」字做锚点反推徽章框（`fine_tune/assets/hud_mi_tpl.png`，15×19）。
搜索带只需 0.855H–0.930H，**0.73 ms/帧**（1280×720 CPU）。
跨会话检出率：有徽章的 6 个会话 75–100%，无徽章的 3 个会话（车尾特写/倒计时/隧道）
**0/20**——没有误检。

**第二步：按线剔除，而不是挖掉那块像素。** 贴脸真线正好从徽章旁边穿过
（f0204 真线 x258–282、徽章中心 x≈322），直接清零概率会把真线一起挖掉。规则改为：

> 一条候选线，若「x 落在徽章横向范围内」且「纵向支撑 **≥85%** 的行落在徽章框内」，
> 判为只长在徽章上 → 丢弃；否则保留。

真线纵向跨 90+ 行、远超徽章高度，比例上不去。

**实测（843 帧，两段会话）**：近带候选线 206 条 → 剔除 37 条，保留 169 条；
**误剔真线 1 条**（206 分之一）。已知假线段 f0590–f0624 里 9 条候选剔除 7 条。
关键帧核对：f0204 真线（x=268，ratio 0.00）保留、同帧徽章线（x=322，ratio 1.00）
剔除；f0202 保留 2 条、剔除 0 条。

**接入位置（生产侧，需裁决后执行）**：`lane_obs._lines_from_prob` 产出候选线之后、
`_out` 的 accepted 判定之前插一道；模板缺失时整道门静默跳过（行为不变）。
代价：**单次推理不变，仅 +0.73 ms**（主模型约 23 ms）。风险：游戏 UI 改字体/位置
需要更新模板；「整条线都落在徽章框内」的短真线会被误剔（实测 1/206）。

产物：`probe_full_session.py`（可复算）、`first_look_out/full_session/`

## 路线判读（调研对问题的回答）

「有没有效果更好的车道线专精模型」拆成两层：

- **架构层有更强的**：CLRNet 系（夜间/遮挡公开数字最强，正对细线与断续）与 UFLDv2（混合锚正对
  远场近水平边线）在公开基准上明显强于基线同族的行锚分类法；但它们都是**线坐标族**，换架构 =
  重写概率图消费端，且 CPU 存疑、DML 依赖深度替换后的算力窗口。
- **数据层是共同前置**：两条路线都必须用游戏画面微调（零微调不成立）。本游戏的几何先验
  （四车道直道、车道线近水平直线、标定已知、帧库现成）使**几何规范化的伪标签 + 小样本全监督
  微调**成为最省人力且可核验的路径——替代公开文献里 LiDAR/外部真值的角色。
- P1/P0 补充实测（见上两节）：同族换权重几乎无差（分界线缺失与模型无关）；分界线主死因是
  生产拟合层的几何设计（扁横条虚线在行扫描+纵向拟合下结构性不可能成线），颜色门/质量门
  几乎不杀。**当下性价比最高的是拟合层按虚线形态重设计**；「从黄缘对合成内部分界线」是
  不依赖虚线的设计候选；微调降级为次要。
- 因此执行顺序是：**① 拟合层虚线化改造（设计定稿后另立实施任务）；② 几何合成方案提请
  方向裁决；③ 微调与 + Medium/Large 补测在①②之后按需评估。**「更好的模型」由实测裁决，
  不由论文数字裁决。

### 远线恢复（2026-11-13）

生产行扫描从概率图第 206 行（≈原图 412 行、约 20 米）开始，是步长 3 时代的
裁切残留；同一模型在 54 米处仍有 0.98~1.0 的线响应。两个只读探针：

- `probe_far_scan.py`：提取层对比。4 会话 342 帧——远段覆盖 13.2 米 →
  25.4 米中位、最远 55 米；近场线横位漂移 p90 ≤0.026 道；80 帧内上移口径
  只多出 2 条短轨迹；画回原图与 20~55 米实际标线吻合。
- `probe_far_tracker_replay.py`：状态机回放。线数中位 4→5、可用率 +1~2、
  TRACK/RELOCK/COAST 分布不变。**边界**：回放喂的锚是近似值（旧会话缺
  实际喂给状态机的深度锚），两臂与实机 trace 的 x 差 p90 约 1~2 道，
  下游自车横位结论不采信。为此 trace 已补 `ro_anchor` 列（观测面，不改
  行为），新会话可精确回放。

生产侧的分段已改为米制单一真源（`ranges.py`）：近 0~15 / 中 15~40 /
远 40~80 米，对应 0.37 / 1.0 / 2.0 秒（41 m/s、20 Hz）。车道线拟合按这三档
逐帧反算行号，远段因透视压缩只剩约 12 行、单独放宽最小跨度。`[lane_obs]`
的 `near_max_m` / `mid_max_m` / `far_max_m` 是这三个数的配置入口。
