# speedrush_agility — 机动时间尺度与躲避触发语义

> **本文是什么**：驾驶侧两个行为假设的离线复算台账——① 横移到位时间（"动作快慢"）
> 对贴边/超车机会窗的压缩量；② "挡道即躲避"与"到站时间才躲避"两种触发语义的覆盖差。
> **本文不是什么**：不是规划器设计，不是规则真源（归 `plugins/speedrush/RULES.md`），
> 不是参数真源（归 `resources/policy/decision.json`）。
> **信源等级**：L4（过程与证据）——结论兑现到 home 后本目录退役，过程留 git。

## 问题

2026-11-07 人工局对照（`20261107_203433` 两段）暴露两个行为差：

1. **动作时间尺度**：人工满杆占 13.1%、换向 48–66 次/分（2026-11-09 手柄复测；
   11-07 记的 37–39% 是原始轴非零占比，不作数）；当时程序满舵 0%，转向量中位
   3536，换向 120–126 次/分。现役闭环律贴 0.68 道约 1.1 s，人工实测同等横移
   0.4–0.5 s。下游所有候选门（邻道到站 ≥2 s、4.5 s 视界、可达性门）都在这个
   时间尺度上开出，怀疑是"慢动作的补丁"。

**满舵脉冲实测（2026-11-09，09:58/10:48 两局四段手柄）**：手柄 `lx` 是 16 位
原始轴，归一化 /32767 后 |·|≥0.9 占样本 **13.1%**（四段 10.3 / 13.4 / 14.6 /
13.9%），段长 P50 0.10~0.12 s、间隔 P50 0.28~0.50 s。旧记的 38~56% 是拿
原始轴直接和 0.9 比，读到的是非零杆占比，作废。程序 `steer_norm` 中位约
0.1、从不饱和，0.14 rad 高挡选中不到 1%；半程反打的 1.0 s 保持与人工
0.10~0.12 s 满杆段不匹配，高挡按 1 s 保持会冲过头后被 `center_dev` 压掉。

**短脉冲台架（0.68 道贴边，带 0.2 s 杆环延迟）**：连续律 k=1.2 到位 1.60 s、
超调 0.100 道、尾段 0.264；回授短脉冲 0.15/0.15 为 0.95 s、0.439、0.714、
满杆 26%，0.18/0.15 为 0.80 s、0.577、0.890、34%，0.18/0.20 为 0.80 s、
0.590、0.382、20%。固定开环脉冲串发散（3 s 到 90+ 道）——人工脉冲依赖
逐拍视觉提前松杆。短脉冲单独上不够：到达更快但超调/摆幅大一个量级，缺件
是释放预瞄；生产候选已落（`short_pulse_*`）、默认关。

**预瞄扩展（_Rig 闭环，0.68 道）**：pass/机动态预瞄接管后到位 1.40 s、
超调 0.037、尾段 0.030、最大杆 0.90、接管 96%；连续律 1.60 / 0.100 / 0.264。
多段交替 ±0.68 的满杆 ≥0.9 占 13~18%，与人工 13.1% 同量级。**整段回放**
（`probe_preview_stage`，旧门 base）：接管 15% 拍、整段满杆 1.8%
（接管窗内 12%，人工同窗 13.3%），脉冲 0.10 s、接管窗内间隔约 0.5~0.6 s
（人工 0.11 s / 0.62 s；整段 4.12 s 是未接管段空档）。

**整段覆盖试验（2026-11-09 实机两局，已回退）**：人工满杆在各门桶里都是
12~13%——并线 12.3、维护 11.6、回中 5.8~12.5、金币 13.2、奖励 12.0——据此把
计划层/意图限制拿掉、连并线也接（`all_nocc`，仍排除有碰撞代价的计划避让与
安全链）：回放接管 60% 拍、满杆 20.2%（含跨道机动态缩放；不缩放 16.2%）。
实机两局（`20261109_225228`）否掉了它：

|---|---|---|---|
| 横向速度过零 / 分 | 31~33 | 31 | **55** |
| 转向换向 / 分 | 63 | 60 | **111** |

得分与前几局同档，极限超车 6~7 次没有增加，两局仍 PLAYER_HEALTH_ZERO。
**杆型不是瓶颈**：旧连续律的横向运动本来就和人工同档；人工的 13% 满杆是在
稳定参考上的修正，程序逐拍追目标把参考抖动放大成可见扭动。抖动来自决策

2. **躲避触发语义**：躲避候选的硬门槛是"到站时间存在且落在 −0.5~4.5 s"；同速前车、
   刚进视野的车算不出到站时间，于是不构成躲避理由，只在回中层做 ±0.17 道的微调。
   人工的触发是"挡着我的道"。

两个假设分开量化，互不混同。

## 标尺独立性

- **slow（现役）**：与 `planner.lane_move_time` 逐位同式（k_lat=1.2、tau=0.25、
  heading_max=0.15 rad、v=41 m/s），用来复现今天的行为边界。
- **fast（快档）**：同式闭环律把带宽提到 k_lat=3.0（`sim_agility.py` 扫描结果：
  0.68 道到位 1.40→0.64 秒、超调 0.075 道、到位后峰峰 0.017 道）。用同一模型保证
  "决策说能、执行也能"；游戏官方紧急档（横向加速度 10 m/s²、紧急横速 5 m/s，
  `RULES.md` §4.3.1）只作上限校验——k=3 的峰值横速约 4.1 m/s，仍在档内。
- 几何照抄选择层现行口径（贴边目标距车心 0.68 道、走廊缘余量 0.35 道、最小间距
  0.6 道、两车半宽和 0.54 道），两档比的是同一批候选、只差执行时间与邻道到站门。

**快档没有超出当前执行能力**：heading_max=0.15 rad 在 41 m/s 下的峰值横速
≈6.2 m/s，高于官方紧急档 5 m/s。差距来自闭环律的**提前减速**（误差收小就把
车头角收回去），不是车辆/杆值上限不够；提高带宽即把这段提前减速推迟。

## 口径

- 输入：控制局 trace 的 `sel_dbg`（每拍自车横位、左右缘、车辆列表 (x, 到站秒)）、
  `otab`（安全资格、米制距离）、`car_pos`（框底行 cy）。五场 20261107 控制局，
  合计 25,901 拍。
- 候选窗与选择层一致：横距 ≤1.3 道、到站 ∈[−0.5, 4.5] s、安全资格为真、
  贴边目标不夹进车内。
- 四组对照：{slow, fast} × {邻道到站门 2.0 s, 1.0 s}。1.0 s = 快档到位 0.73 s +
  反应 0.13 s + 余量 0.15 s。
- 挡道口径：同道（|Δx| ≤ 半宽和 0.54 道）且近距（米制 ≤30 m 或框底行 ≥600 px，
  后者是对象表判近的同一口径）。

## 判读

1. **动作时间尺度是机会窗的第一压缩因素**：把执行带宽提到 k_lat=3.0、邻道门随之
   收到 1.0 s，可达候选的拍占比从 23.9% 提到 39.7%。快运动学与门放宽各贡献一半，
   且两者叠加优于单改。这支持"先改执行律、再让门随执行能力收缩"，而不是在慢
   动作上继续调门限。
2. **挡道语义是低频致命项**：覆盖增量只有 0.28 pp，但命中的正是"算不出到站时间
   的近距同道车"——撞车复发的位置。它不能提升日常得分率，但能消掉一类可复现的
   事故；按"鲁棒性优先"的既定取向，值得独立实现。
3. 两者互不替代：只改运动学，撞车场景仍在；只改语义，机会窗不增。

贴边保持闩在「目标车不接近」时不会释放（274 段里 131 段到站时间不下降），

**第二批（`20261109_103934`，2 程序局 + 1 人工）已证横距口径不可用**：判定帧
就是被超车贴着自车侧方的时刻，横位读数最差；某阶段实际派了 6 个动作事件，
7 个掠过点在横距上全被分到「接触/欠调」。得分验收改用横幅真值
（`probe_action_events.py`）：程序每阶段 4.1→4.8 个动作事件，而分速档位占比
反推人工约 10~12 个/阶段——分速是短窗统计，占比≈动作密度，瓶颈是动作次数。
同一批里窄死区确实生效（计划选中意图跟踪候选 27%→46%、轨迹终点偏差
0.53→0.10 m）；分速没动（≥120 档 17%→18%），人工对照同期从 108/132 涨到
151/138——批次差异压过改动。**分速单批持平不否定窄死区改动**：行为指标
（终点偏差、意图跟踪入选率）已往人工方向走；验收口径按计划文件「验收口径」
——行为对齐人工优先，分数作多批滞后结果，不作单改动准入。

### 近场身份连续性真值小集（2026-11-10）

`probe_identity_truth.py`：把人工 120 分超车事件的对到 trace，从判定拍按
候选链回溯（闪烁 ≤4 拍容忍、真断时按位置/框底距离找替代 oid），回答三问：
编号在哪一拍断、断时两读数差多少、断后新号是不是原车。链只是候选——
同编号跨拍不保证同一物理车，最终裁决靠标注帧目视（`--figs` 出事件图包：
框底/框顶行横线 + 链内红/橙、链外灰，按左上文字行读 oid/x/t/zg；横向
透视反推在近场发散——xl 0.74 道反算 cx 出画，不画横向框）。

读数（41 可判事件，两局人工 trace）：

| 量 | 读数 |
| --- | ---: |
| 1.2 s 处 same / none / renewed | 36 / 4 / 1 |
| same 链内最大横位跳 P50 / P90 | 0.78 / 2.01 道 |
| same 里横跳 >0.8 道（读数不可信） | **18（50%）** |
| 并存误接链（新旧号同时活着被串一链） | 3 |
| 特征黑洞（表空窗 ≥0.3 s 且 ego 单窗跳 >2 m） | 2 |
| 修正口径：同号且链内读数连续 ≤0.8 道 | **18/41（44%）** |

结论与裁决（细节见 `docs/plan/交接_近场车辆身份连续性.md` §10）：真断号仅
1~2/41（特效黑洞后重挂 Δx ≤0.5 道可接）；主要矛盾是**号不干净**——并号
（一号先后挂两辆车，目视 3/3 确认）与锚错挂占 same 的一半，方向排序改为
多源一致性/未知态优先，外形连续性兼做并号检测，纯位置重挂只做特效后专项
并配并存检查。

坑：

- trace 的 `fid` 只在 stage 内唯一、跨回合重复（103934 一份 trace 里
  fid 3337 相隔 9 分钟各出现一次）——按 fid 反查拍会撞到别的回合，一律用
  ts/拍索引定位；判定拍对齐还要容 dispatch 日志滞后 0.5~1.2 s（浮字
  先于日志落盘）。
- 判定拍附近可能有一帧全屏特效：那是**撞上磁暴车触发引爆**（RULES §4.2，
  范围内车辆物理退场 + 特效帧感知全瞎；跳板车无此特效）——表空窗一部
  分是这一帧/这一场清场盖住的，别归因到超车判定本身。
- 近场横向透视反推发散：`car_pos[].x`（道）× (cy−地平线) 反算 cx 出画，
  与画面车辆对不上——只有框底行可靠，横向认车靠目视。
- 人工 trace 的 objs z 普遍为 None，纵深用框底接地距离
  （`_ground_z`：焦距·机高 ÷ (框底行−地平线)，机高只认 1.0~1.6 m）。

### 并号拆分离线复算（2026-11-10）

`probe_split_shadow.py`：真值小集发现 same 事件一半链内横跳 >0.8 道（并号：
一号先后挂两辆物理车）后，验证「拆号」能救回多少。复算语义：相邻读数
（拍距 ≤4 拍）横位跳 >0.8 道即拆点；拆点按并存证据分型——新位置 0.35 道
内有另一 oid 的读数（与旧位置可分）→ merge（两辆物理车），否则 artifact
（读数伪跳/换锚，拆了会把同一辆车改名）。1.2 s 身份可用按拆号+去重语义
计：窗内无 merge 边界，或判定车经并存编号（第二辆车自己的号）干净接回。

三源（两局人工 + 164024 基线）scale：裸拆触发 34~63 拆点/分钟、轨道碎成
P50 6~9 簇——**拆号不能裸用**；拆点里 merge 型仅 ~33%、artifact 型 67%。

41 个人工 120 事件（36 个 same）：

- 基线（全链横跳 ≤0.8，真值小集口径）：18/36 = 50%（44% 按 41 分母）。
- 拆号+去重语义身份可用：**32/36 = 89%**——merge 型并号 9 个里 5 个经
  第二辆车自己的编号在 1.2 s 干净接回（fid2726/2935 等目视并号样本与
  语义吻合）、4 个接不回（并存编号 1.2 s 处缺读数或也脏，fid3241/3897
  的并存误接就在其中）。
- 「89%」里 9 个是「身份对但读数伪跳」（artifact 型，拆号不管）——干净
  可用率按「同号且读数连续」仍是 50%+5 接回；artifact 伪跳是横位未知态
  的领域，两者互补不重叠。

结论：拆号以**并存证据为门**可用（跳 >0.8 道 + 新位置有另一 oid 才拆/
去重，旧号终止让位并存号）；裸拆禁止（67% 拆点是伪跳、轨道会碎）。

**artifact 拆点目视标注（同日）**：21 个脏事件窗内 artifact 拆点全量
出图（`--figs`，拆点前后帧对照）目视：**90%（19/21）是纯读数伪跳**
（同一辆车：自车横移致车道坐标跳 2、近距擦过/出画框底行滑出 8、远场
小位移横位跳 9），真并号（无号车）1 个（fid1412：链从远车跳到近处
红出租车，两车同时在画面、出租车无自己的号）+ 存疑 1 个（fid2541）。
判读：①裸拆禁止被目视证实；②以并存证据为门的漏判面小（5~10%），门
成立；漏掉的无号车并号要覆盖走外观连续性判据（方向 3 两用）。注意
fid2935 的目视并号不在 artifact 拆点里——挂上那一刻的跳变被 chain
回溯当正常读数，artifact 拆点是挂上之后同一辆面包车的自车横移跳。

### 贴边翻面×纵深跳变构成拆解（2026-11-11）

`probe_zflip_anatomy.py`：未知态 A/B 组 90 次贴边目标翻面里 47 次与纵深
跳变/断供同拍（`probe_x_z_coupling`）——按设计该被横位未知态截住却没截。
本探针把这批按四个维度拆构成（z 来源/锚龄/同道邻道/修正项占比 + 换车
vs 同车读数跳）。204716：翻面 62 次（纵深耦合 37 / 平稳 25，与 47 同
量级，差值是 mcars 可用性口径）：

纵深耦合 37 次的构成：

- **换了目标车 30（81%）** vs 同车读数跳 7（19%）——纵深耦合翻面的主体
  是选择层切目标，不是同车读数跳；平稳翻面正好反向（同车读数跳 80%）。
- **桥接 z 在场 30（81%）**——「纵深跳变同拍」的 z 大多是框高比桥接的
  阶梯（3~7m，按设计是测量噪声、不触发换锚重置），不是真纵深跳变；
  耦合是巧合伴生。
- 锚龄<200ms 刚重锚 15（41%）；同道目标 11（30%，未知态设计不滤）；
  **修正项主导（|Δc|≥0.5 道）仅 5（14%）**——z_reset 弯道修正病灶不是
  主力。
- 切换前拍旧目标满足未知态触发（z_reset/横位跳）的只有 6/46——换车
  大多**不是**弃车过滤的设计行为，是正常重选（候选更优/旧目标丢失）。

判读：① 47 次耦合的 z 大多是桥接阶梯，耦合不等于因果；② 纵深耦合翻面
的主体是选择层切目标（选择层任务），同车读数跳只有 7 次——身份匹配
任务内真正对症的翻面非常窄；③ ①②③ 观察点合起来解释 89%，其中桥接
z 盲区（②）是最大成分。复跑：`probe_zflip_anatomy.py <会话>`。
