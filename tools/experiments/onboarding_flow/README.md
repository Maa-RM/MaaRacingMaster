# onboarding_flow — 首次使用引导（真实前端 + 聚光灯）

在**真实前端**上验证首启体验：纯色声明页硬阻塞，之后用聚光灯指向真实控件，引导用户自己点。
`live/` 是生产前端的完整副本，只多了 mock 后端与引导层；正式实现里状态由后端持有。

## 目录

- `live/`：真实前端副本 + `mock-backend.js`（桥桩）+ `tour.js` / `tour.css`（引导层）。
- 根目录的 `index.html` / `onboarding.*`：早期独立骨架，只作对照，不再是主演示。

## 怎么打开

在仓库根起本地服务，访问 `live/index.html`（推荐）：

```powershell
.venv\Scripts\python.exe -m http.server 8766 --directory tools/experiments/onboarding_flow/live
```

然后打开 `http://127.0.0.1:8766/index.html`。

URL 参数（`?` 或 `#` 均可）：

- `?reset=1`：清进度。
- `?view=gate`：只看声明页。
- `?view=tour&step=N`：跳过声明，直接看第 N 步（从 0 开始）。
- `&snap=1`：关掉引导层动画与倒计时，用于截图。

## 流程

1. **声明页**：整屏纯色，没有卡片、进度条和步骤圆点。5 秒阅读倒计时，「同意」期间禁用；
   不同意即退出。
2. **聚光灯**：遮罩在真实界面上挖洞，只能点高亮目标；除高亮区外弹窗其他部分也不可点。
   每步等**结果出现**才前进（弹窗真打开、任务列表真出现项、真切到设置页）。
3. 路径：打开模块管理 → 加入启动游戏 → 加入关闭游戏 → 确认列表 → 切到设置 →
   打开运行环境。只覆盖两个内置步骤，不涉及任何活动模块；模型权重在模块自己的卡片里安装，
   不在引导范围内。

## 验收点

1. 声明页 5 秒内「同意」不可用，最小化或失焦不影响计时。
2. 点击高亮目标能推进；点遮罩其他位置不推进，气泡抖动提示。遮挡层只拦非目标区域，
   高亮区域必须真正穿透到控件。
3. 每步判据是结果状态：点开弹窗、任务列表真出现项、切到设置页，不是点击事件。
4. 严格阻塞：除高亮目标外，弹窗里的其他卡片、关闭按钮都点不到。
5. 跳过本步后，下一步不能带着上一步的抖动动画。
6. 中断续做：刷新后回到当前步骤，页面状态由该步自己重建。
7. 声明改版：只改文案版本、不改程序版本也会重新出现。

## 与正式实现的对应

- 声明状态、引导进度、目标 id 都由后端登记；前端只按登记表渲染和定位。
- 每个步骤的目标选择器必须能在真实页面结构里找到，改了控件名不改引导，机检会红。
- 默认任务列表清空，由引导带用户建立；引导只覆盖启动/关闭游戏。
- 模型权重在模块卡片自己的安装入口，不在环境中心，也不在引导里；环境中心只讲系统权限、
  手柄驱动和运行组件。

## 边界

- `live/` 里的业务数据全部来自 `mock-backend.js`，不连 Python、不写生产配置。
- 声明文案是占位示例，正式文案需另行定稿。
- 结论落到正式文档后，按实验区规则删除本目录。
