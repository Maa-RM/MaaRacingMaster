## 背景与口径

- 第一轮遗留：MoGe-2 相对最准但延迟过高；DA-S 有视差反投影的结构性塌陷；metric 家族在几何平整度上实测占优。
- **本轮口径（维护者定调）**：不吃超远场（远带已在真机上吃过亏），**专注中近场快速更新**。
- 预算沿用第一轮定调：深度模型纯推理 ≤70ms（10Hz 地板）/ 40-50ms（舒适档）；DML 锁不得增并发（并发 run 段错误是第一轮实证）。
- 判据沿用第一轮：中近场的近远序、路面/墙基平整度、墙基-路面边界锐度；自监督候选（Lite-Mono）逐帧尺度不稳，须配尺度锚（同帧近场双车 |Δcx| 锚）。
- 输出方向统一坑（带入本轮换算）：yolo26-depth 输出 log 距离（大=远）、DA 系视差（大=近）、MoGe / DA3 直出深度。

## 采纳清单（委托调研，豆包 2026-11-11；原文不进树，只收采纳与更正及理由）

- **采纳**：DepthART 全家（现成 ONNX、公开 KITTI 数字、relative 8.3MB 起步 + metric S448 补上「小+米制+驾驶场景」空档）与 ZipDepth（ECCV 2026 轻量零样本，社区 ONNX 现成）。
- **采纳为 baseline/兜底**：MiDaS v2.1 small（KITTI 精度全表最低、驾驶不占优，但零依赖单文件）。
- **不采纳及理由**：GLPN-KITTI（唯一 Apache+KITTI metric，但 245MB、fp16 后 122MB 超线、速度不占优）；monodepth2（KITTI 出身速度友好，但 99MB 需自导出且许可非商用）；LapDepth-KITTI（295MB 无 ONNX）；Distill Any Depth Small（架构即 DA-V2-S，与已排除候选无速度差异）；LingBot-Depth（是 depth completion，非 RGB→depth）；ONNX Model Zoo（已无深度模型）。
- **调研方未核实、留给本轮实验的点**：DepthART metric 系喂假内参的绝对尺度漂移幅度（游戏画面无真内参）；ZipDepth fp16 导出质量；DepthART MNV4-S 与 M 档精度差是否剪枝所致。

- **近远序全部 +1.000**（序正确且完美单调）——该指标在本段饱和，不区分质量。
- **路宽定标**：底部行量法作废（该处路宽超出画面两边、量到画幅截断的 7.4m 假读数）；全幅 14m 尺改在「路缘两侧都进画面」的行上量，见「结论·续」。
- **目检（`bakeoff_out/sanity_frame0103.jpg`）**：路面梯度与远处结构各模型均可辨；MoGe 对近处卡车读数方向正确；HUD 文本框被部分模型读成近景亮块（HUD 在行 0~120，全部判据带之外，不影响指标）。

## 结论·续（融合测距：锁定出租车，2026-11-11）

生产同款融合（复刻，不 import 业务代码）：perception 检测（640 letterbox、conf 0.35、NMS 0.45、ROI (0,201,1280,561)）→ 出租车跟踪（种子=全帧最大 car 框，双向最近中心匹配）→ 框底条带（底部 25% 行）中位距离（生产 `_box_anchor_z` 2026-11-04 修正版口径）。跟踪 15/18 帧（帧 0089 远车失检、末两帧贴脸失检）。期望落差按**跟踪段**算：41m/s × Δt（frames.jsonl 真时戳）= 75m（帧 90~104）。

| 模型 | 帧 90→104 距离序列 | 判读 |
|---|---|---|
| **MoGe 生产 q4f16**（米制 ×0.893） | 64.5→69.6→68.0→61.9→49.7→…→36.8→29.0→9.1→19.8 | **结论级**：平滑衰减、末段贴上；落差 44.7m < 全油门 75m 与「前车同向运动」自洽（相对合拢 ≈19m/s），非模型错 |
| MoGe-2 ViT-S fp32（路宽尺标定） | 125.7→…→58.0→18.0→36.7 | 形状同上但绝对值 ≈2× 生产标定——路宽尺与生产 depth_scale 差 ~2×，见下 |
| DepthART MNV4-S（路宽尺乘法） | 93.5→…→40.5→15.7→33.3 | 形状接近但早段偏高 ~45%——仿射偏移的乘法近似残差 |
| ZipDepth fp16（路宽尺乘法） | 352.7→…→73.6→19.2→36.9 | 早段 ×5 虚高——带仿射偏移，乘法尺失效 |
| yolo26n（路宽尺乘法） | 36~45 平坦无衰减 | 失效（log 距离的乘法换算不成立） |
| MiDaS small（路宽尺乘法） | 72→150→15 乱跳 | 失效 |

- **融合链路结论**：metric 家族（MoGe 生产标定）给出结论级出租车测距；**相对模型的乘法尺只对「深度比例」模型成立**，带仿射偏移的模型（视差向/逆深度向）需要**两点仿射标定**（两个深度处的路宽尺），这是相对模型上产测距的前置工程。
- **路宽尺修复生效**（2026-11-11 更正：帧 0089 是干净路面，此前 7.4m 是量宽行选错——底部行路宽超出画面两边、量到画幅截断）：改在「路缘两侧都进画面」的行上量，干净帧全幅路宽 ~1000~1190px（MoGe fp32 1012~1064、ZipDepth 1153~1189、lite_mono 887~1075），14m 尺可用。
- 路宽尺（MoGe fp32 路径标定）与生产 depth_scale(0.893) 差 ~2×：生产标定出自画线金标（2026-10-29 九局 6,400+ 对相邻线间距），路宽尺出自本段单帧——以生产标定为准，路宽尺待多帧金标核对后才能做独立交叉验证。

## 结论·续二（多段 rate=41 帧集：乱跳度量，2026-11-11）

数据集：hud.jsonl（每帧 HUD 解析存储）里 trusted rate=41 的帧共 63 帧、6 段 ≥3 帧，已拷入 `frames/*_rate41/`（meta 含 seq/frame_id/ts）。两个乱跳度量（维护者定调：不能接受接近中乱跳，甚至同一张图都乱跳）：
- **时序乱跳**：相邻跟踪帧 |Δd|（>5m 计跳）与合拢速率散布；
- **同图乱跳**：同一帧内 框底条带（生产口径）vs 整框中位 的读数差（生产已知整框口径同图内不稳定）。

## 结论·续三（小号模型可视化核实，2026-11-11）

`bakeoff_out/overlay_20261111_104222_p2_rate41.jpg`（3 跟踪帧 × 6 模型，深度热图亮=近，白框=出租车，黄框=生产口径的框底条带采样区）：

- **MNV4-S / MiDaS 的同图差 0.0 = 超平滑退化，不是真稳定**：两模型输出是「团块渐变图」——路/车结构几乎不存在，车影是位置不跟车的暗团（seq50 车已到左侧，暗团仍居中）。底带与整框中位在这种图上必然重合，0.0 是退化读数，不采信为优。
- **yolo26n / Lite-Mono 是真结构化**：车轮廓（含车轮形状）、路面梯度清晰可辨，同图差小可信。
- **ZipDepth 二值化外观 = 显示层截断伪影，修掉后显示正常**（2026-11-11 更正）：ZipDepth 原始输出 32% 精确 0 像素、集中在顶部天空带（行 0~192 占 61-81%，逆深度远场饱和 0）；取倒数时对这些 0 做下限截断 → 天空带变成同一平顶值 + 硬边界 → 热图呈二值化假象。改为 0 值按无效 NaN 后重渲染：天空带退出、路面平滑渐变、车影可辨——中近场（行 192+）几乎无 0 值，判据带与乱跳度量不受此影响。ZipDepth 的中近场显示实际是平滑结构化的。
- **Lite-Mono 奇怪外观 ≠ 管线事实性错误**（2026-11-11 逐项核对官方 test_simple.py）：RGB（pil convert RGB）、ToTensor(/255)、**直接拉伸无 letterbox**（官方即如此）——三步全对；ONNX 解码器已含 sigmoid（原始输出 0.02~0.56 即视差域），1/视差序数正确，官方 disp_to_depth 的 min/max 仿射只改远端绝对值不改序数。怪的来源是 **16:9 内容压进 10:3 的极端纵向畸变**（720→192 纵向压 3.75 倍，官方在 KITTI 10:3 上训）+ 该模型 CNN+transformer 混合输出特性——喂 16:9 本来就是错位感，其在仓可用性打折，除非做水平 tiled 裁剪推理。
- MoGe 生产权重：平滑且结构化、车影位置跟车，参考质量成立。
- 共同形态（未核实成因）：被超车的近距左侧车区域在六模型上读数一致偏远（seq50）——与第一轮「车上读数各模型分歧巨大」一致，近车读数不可信是共性短板，非某个模型独有。

**对判决的含义**：同图乱跳指标里「恰为 0」的模型先按退化排除；剩余候选里 yolo26n/Lite-Mono（真结构化、同图差小）与 MoGe 生产权重（米制、居中）是形状上可信的三家。ZipDepth 的二值化是显示层截断伪影（已修），中近场显示平滑结构化——但乱跳度量（时序跳 4 次、同图差 p95 22.6m）不受伪影影响、仍是全场最差，快速线里仍排后。终选仍待时序功率补足后的多段验证。

## 结论·续四（校准对齐设计：生产 MoGe 米制，其余=换后端走车道宽仿射，2026-11-11）

维护者定调校准方案：**校准（米制）是给生产 MoGe 用的；其他模型 = 换了个后端**，统一借助车道宽度出尺度，再把渲染的值→颜色映射统一（最近/最远在所有模型上同色），才有可对比性。`render_aligned.py` 按此实现（校准 1 两点仿射走车道宽 + 校准 2 共享值域 + 校准 3/4 每帧一网格）：

- **尺度怎么出**：生产 MoGe = 米制直读（gate0 ×0.893）；其余模型（换后端）= 两点仿射 `depth = a·V + b`——近点：底部「路缘两侧进画面」行的全幅路宽 = 14m（四车道 ×3.5m 画线，fx 取 gate0 的 670.7），与出租车框相交的行不取；远点：同帧地面透视关系外推 `z2 = z1·(r1−v_h)/(r2−v_h)`（锚定地平线 354.2）。解不出两点的帧如实标注 percentile（未米制）。
- **校准后的读数（seq48，框中出租车）**：仿射模型一致读 ~26m（moge2 26.4 / zipdepth 26.0 / lite_mono 23.9），生产 MoGe 读 9.8m。**按路宽标定，该条带行的路面物理深度本就在 25~30m**——仿射模型与车道宽几何自洽，生产 MoGe 的 9.8m 偏近（条带可能混入前方路面，待核）。
- **深层张力（已裁决，2026-11-11 维护者定论）**：车道宽标定与生产地面透视的 ~2× 差异归因到 **cam_h≈2m 旧口径**——那是含追逐视角的历史读数带；项目现役只用保险杠视角，保险杠相机离地高权威口径 **1.25m**（逆向三视角对照 + 创意工坊实测，前向 1.70m），不再待裁决。
- **渲染**：全模型共用 MoGe 米制校准后的 p2~p98 值域（seq48 [3.94, 117.07]m），turbo 近=亮暗=远；对齐图上仿射模型的中景读近（橙）、生产 MoGe 读远（navy）——**大面积深色是真实分歧的暴露，不是置黑 bug**（≤0 外推与 NaN 按无效处理）。两套尺子下「谁读得对」正是要对比的东西。
- **校准后对比图已出（2026-11-11 锚落定后，`render_calibrated.py`）**：两组图同一校准、同一值域、同一颜色语义（近=亮橙、远=深蓝紫、无效=灰），平方根非线性映射（中近场拉开），共享值域 [2.1, 45]m（远端物理截断——仿射模型的虚大读数会把值域拉宽压扁中近场梯度）：
  - `calibrated_compare.png`：MoGe-2 / monodepth2 / yolo26n / Lite-Mono；
  - `calibrated_compare_rest.png`：MoGe 生产 q4f16 / yolo26s / yolo26m / ZipDepth / DepthART MNV4-S / MiDaS。
  全部模型金标行读数跟踪金标（行 500 全部 ≈5.8~6.2m 对金标 5.75m，行 650 ≈2.6~3.7m 对 2.83m）。
- **淘汰（维护者 2026-11-11 目检校准后对比图定案）**：**monodepth2、Lite-Mono 效果太差**——monodepth2 结构糊（640×192 低分辨率立体自监督，地平线结构弱）；Lite-Mono 极端纵向畸变（16:9 压 10:3）团块化。仍渲染存档，不进候选。

- **公平性排查（2026-11-11）**：①**仿射标定质量全部过关**（地面行中位相对残差 0.8~3.7%、最大 5.3%）——标定不是干扰源，判据公平；②**输入格式不对称**：MoGe/ZipDepth 原生 16:9 无畸变，yolo26 全系（768×768）/DepthART（448×448）/MiDaS（256×256）方形输入内容压 1.78×，两个 mono（640×192）纵向压 1.87×——模型自带的 handicap（各自官方/设计输入格式，生产同形态），非管线偏袒；③MiDaS 输入写死 256×256（0.065MP，MoGe 的 1/14 像素），免 torch 导出无法换档，rough 是输入格式自带；④共享值域远端物理截断 45m 已做。**结论：判决无系统性不公，评的是「模型+其输入格式」整包，即生产形态**。Lite-Mono 换 1024×320 档畸变仅 1.87×→1.80×、水平 tiled 在 16:9 短帧上凑不出 10:3 瓦片——重新渲染收益小，不值得。

- **yolo 出局 + MoGe 定位（维护者 2026-11-11）**：yolo 系全档被对比图与计时淘汰（结构与速度均无优势）；MoGe 定为**形态/质量参考**——速度绝对比不过另两家，不参与竞速。
- **DepthART 的取舍（2026-11-11 模型卡+ONNX 核实）**：官方 = ACM MM 2026「Scaling Foundation Monocular Depth to Tiny Models」（xuefeng-cvr/DepthART），把 Depth Anything 家族基础模型压进 TinyViM/MobileNetV4 小 backbone——快和小由压缩而来。代价：
  ①**原生输出只有深度图**（image → depth），没有 MoGe 的 mask/points/normal/scale 四件套——生产链路的供数有效性屏蔽、路面平面拟合（→相机高→视角守卫）都吃 MoGe 的点云/掩码，换 DepthART 这两条要另起炉灶；
  ②**metric 档需要相机内参输入**（RGB+intrinsics→meters），游戏无真内参（禁写死焦距）且纯 ORT 跑不了 metric 档（需自定义算子/TensorRT 插件）——相对档 → 米制靠逐帧仿射（已建，地面行拟合残差 0.8~0.9%）；
  ③输入 448×448 方形，0.2MP（MoGe 的 1/4.6），内容压 1.78×；
  ④结构超平滑团块化；
  ⑤MNV4-M-slim-SPF 变体（剪枝+SPF 解码器，官方称质量/速度平衡更强）需 torch 导出，仓内 ONNX 只有 MNV4-S/M default。
- **slim-SPF 已拉（2026-11-11）**：官方仓**现成 ONNX**（`relative_mnv4m_slim_spf_448_default.onnx`，24.2MB，无需 torch 导出）。DML 推理 5.91ms（MNV4-S 4.10 / MNV4-M ~7.4ms），24.2MB；结构对比（`slim_spf_compare.png`）：**三档里结构最好**——地平线细节（远处车辆、路灯）与 MNV4-S 相当且更平滑，官方「质量/速度平衡更强」成立。**MNV4-M 退化实锤**：仿射拟合 a≈0（地面行 V 无方差），米制换算崩、整图发白——M 档不可用。
- **生产集成面（2026-11-11 盘查，开工前置）**：缝只有一个——`depth_geo.infer_points`（moge_post.forward + reconstruct）产出 (pts H×W×3, valid, diag)；module.py 的全部消费者（视角守卫 cam_h=coef[2]、边缘检测 sides/left/right、far_extents、_box_anchor_z）只吃该产物，`normal` 输出无人吃。**大块删除重构**（非改写）：infer_points 的 MoGe 分支整体删，换 DepthART 分支（depth → 近=小 → 逐帧地面行仿射，已建可复用）。**唯一新决策是焦距**（DepthART 无逐帧焦距，RULES 禁写死）：A 混合供数——MoGe 降频跑供 mask+逐帧焦距+相机高（视角守卫本就低频），DepthART 每拍供深度（推荐）；B 从 depth 图地面行仿射解 f·cam_h 配车道关系解 f（循环嫌疑，需验证）；C 固定标称内参违反 RULES，排除。mask 替代：valid = z>0+有限性+现有尺度门，或感知掩码。module.py 不动（吃 dgeo 接口）。

## 结论·续五（车道线金标：逐行深度样本 + 米制模型偏差系数，2026-11-11）

维护者定调：①有米制输出的模型**和 MoGe 同一药方**——金标行上测偏差系数，系数入单入口后继续米制直读（不弃米制头）；②车道线模型结合单车道宽做金标（有透视有宽度）。`probe_lane_gold.py` 按此实现：

- **金标性质（无焦距直接裁决）**：车道线模型给每行车道线像素，相邻两条线的像素间距 ↔ 3.5m（四车道画线）⇒ 生产地面关系 `x_px = VPX + L·LANE_W·(y−Y_H)/cam_h` 反解 **`cam_h_implied = LANE_W·(y−Y_H)/Δx_px`**——不需要焦距、没有尺度歧义，车道线可见的行逐行一个样本。
- **测量结果（撞出租车段 18 帧）**：516 个金标行，逐帧一致——**间距 ×2 修正后 1.05~1.15m、中位 1.114m**（未修 ×2 时 2.13~2.36m/2.228m 是横向尺度混用假读数；更早首版 5.50m 是公式写反）。反推值与权威锚 1.25m 差 −10.9%，作交叉核对不作锚（残余候选：Y_H 地平线行、letterbox 映射、权威 1.25m 的口径参考点）。（首版 5.50m 是探针公式写反——`cam_h = LANE_W·(y−Y_H)/间距` 被写成乘间距；2026-11-11 修正。）
- **米制输出模型的偏差系数**（方法：金标行上 median(z_gold/model_metric)）——**中间历史值 ×1.48 / ×0.10（锚=2.228m 假尺）已作废**，最终值见下条。
- **张力已裁决且成因落定（2026-11-11）**：项目现役**只用保险杠视角**，保险杠相机离地高权威口径 **1.25m**（逆向 cameramode_normal/1443.xml 三视角对照 + 创意工坊实测）。2.228m 假读数的成因 = **横向尺度混用**：车道线模型输入 640 宽（全幅 1280 的一半），分段间距量出来是 640 尺度像素；生产地面关系的 x_px 是 1280 全幅——间距未 ×2 使 cam_h **恰好虚大 2×**。×2 修正后 204 行中位 **1.133m**，与权威 1.25m 差 −10.9%。

- **18 帧段视角归属落定（2026-11-11）**：间距 ×2 修正后反推 cam_h 1.05~1.15m，与保险杠权威口径 1.25m 自洽（±11%）——**该段就是保险杠机位**，原「追尾/追逐视角带」的裁决是横向尺度混用假读数的产物，作废。视角切换守卫的生产事实仍成立：刚开局游戏会切视角，守卫按 RB 最多切 3 个，以相机高中位落入 [1.12, 1.55]（保险杠机位确认带）判停，确认后记实例、p2 不再查——守卫的目的就是把被游戏打回的追尾机位**切回保险杠**（`module.py` 视角守卫，2026-11-11 核对）。
- 偏差系数（**已按权威锚重算，2026-11-11**）：moge2_vits fp32 metric 头 **×0.829**、monodepth2 ms640（×5.4 立体基线）**×0.059**——516 个金标行，锚 = 权威 1.25m（`z_gold = FX·1.25/(y−Y_H)`，FX 取 gate0 的 670.7）。旧系数 ×1.48 / ×0.10 挂在 2.228m 假尺上，作废。系数入适配器单入口后继续米制直读。生产 MoGe 的 depth_scale=0.893 同源（gate0 九局 6,400+ 对相邻线间距 1.16 控制道按 3.5m 画线反推）。
