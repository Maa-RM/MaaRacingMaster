# achievement_collection — 成就收集页与入口形态

status: active

## 这个原型回答什么

成就收集页的**入口位置**与**页面组织**：

- 不占一级导航的前提下，入口放在标题栏按钮上是否够显眼、够轻；
- 「按钮 → 整页覆盖层」这种打开方式，与数据页子视图相比是否更符合成就的独立地位；
- 页内按「核心 / 各模块」分组后，用户的浏览路径是否清楚；
- 四档描边在网格里（而不是在提示条上）是否还成立，隐藏遮蔽读不读得懂。

## 产物

`preview.html` —— 单文件、零依赖，浏览器直接打开。标题栏右侧「成就」按钮打开整页覆盖层，
页内含概览条、筛选行、按「核心 / 极速狂飙 / 鉴宝」分组的成就网格。

## 当前形态

- **入口**：标题栏按钮（奖杯 + 已解锁数），不占一级 tab；点击打开覆盖标题栏以下的整页。
- **分组**：核心自成一组，其余按 `mod_id` 归组；每组带 已解锁/总数 与一条细进度。
- **概览**：总进度、四档分布 x/y。
- **筛选**：全部 / 未解锁 / 已解锁，筛选作用于所有分组，空分组自动隐藏。
- **卡片**：档位色 2px 外圈；未解锁整体转灰；隐藏未解锁显示「？？？」与「解锁后揭晓」。

## 已知缺口

- 核心成就目前没有来源：`registry._discover_plugins()` 只扫插件 manifest 的 `ACHIEVEMENTS`，
  `global_id` 恒为 `mod_id.id`。要支持「核心自带成就」，需要新增一个 core 级目录来源。
- `max` 类进度（越大越好的数值）在卡片里没有合适表达，当前示例避开了这类成就。
