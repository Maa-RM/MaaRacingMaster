# ADR-0027（contract-core）：模块资产安装由插件声明，宿主只授予命名空间与生命周期

- **状态**：`accepted`
- **日期**：2026-11-21
- **决策者**：用户（确认「未来所有模块都可以自行下载所需资产」的方向）
- **相关**：[宪法 §1/§4](../PIPELINE_V4.md)、[ADR-0016](./0016-contract-core-模块配置面板由插件声明宿主渲染.md)、`maaracing_master/core/CODE_WIKI.md`「用户数据目录」、commit `f9f9c41`

## 背景

深度模式与线观测的 ONNX 权重体积大，不能进默认主包；用户需要在不手动解压、不重装程序的前提下补装。项目同时有三条硬约束：用户数据根与程序内容根分离，升级只替换内容根；插件可复制即装、删除即卸，core 不得长出模块字段分支；前端只能发逻辑动作，不能指定 URL、目标文件或路径。

这组约束下必须回答一个跨模块问题：**「模块想下载自己的资产」时，谁决定下载什么、落在哪里、什么时候可用**。答案会长期约束后续所有带下载需求的插件，也会决定宿主是否会滑向通用下载器或资源商店，因此单独立此条。

## 决策

1. **落点**：模块发起的下载字节一律落在用户数据根的 `data/<manifest.ID>/` 内，程序内容根永不作下载落点；暂存（未完成下载、解压中间态）与已安装资产分层，已安装资产按内容摘要分目录，摘要不变则跨程序版本复用。目录只能经 `paths.module_data_dir()` 获取，该入口拒绝绝对路径、盘符、`.`/`..`、分隔符与解析后越界。
2. **信源归属**：文件级清单、尺寸、SHA256 归插件代码；发布 tag、资产文件名、包哈希与展开尺寸由构建生成的下载描述随主包分发。宿主不复制清单、不从展示版本字符串反推文件名，也不回读自己写出的生成物。
3. **宿主接缝**：插件在 manifest 声明 `ASSET_INSTALLER` 指向自己的安装器，并声明安装入口的显示名词与缺失提示；宿主按声明加载与转发，状态只收模块无关的公共字段，前端只传模块 id。宿主不认识任何模块的资产语义。
4. **生命周期**：安装与游戏运行、升级冻结在同层双向互斥，且判定在后端受理锁内完成，不依赖前端置灰；关闭时先拒绝新动作，再取消安装并做有界收尾。
5. **不建通用下载管理器、资源商店或独立更新服务**。第二个真实下载模块出现之前不抽公共传输层；届时抽取也只能在插件之上做，不得改变本条第 1–4 款的归属。

## 后果

**收益**：带下载需求的新插件只写 manifest 声明 + 自己的安装器，宿主零改动即可获得入口、进度、取消与互斥保护；升级替换内容根不影响已装资产；宿主没有模块字段分支，删插件即卸能力。

**代价与约束**：

- 每个下载模块自行实现传输、校验、解压与提交，重复成本由插件承担；宿主无法统一改下载行为（限速、镜像、断点续传都要逐模块做）。
- 各模块必须自行保证跨进程提交互斥与中断恢复，宿主只提供单实例内的准入。
- 清单变化换目录意味着旧版本目录不会自动清理，磁盘占用由用户决定何时回收。

**被否方案**：

- **宿主通用下载管理器**（URL/进度/取消/校验/落点全归宿主）：宿主必须认识模块的资产字段，形成第二份真源，并滑向资源商店与独立更新服务，与 MaaFramework PI V2「资源版本对应唯一 UI 版本、UI 不做独立更新」的约定相悖。
- **下载进程序内容目录**：Velopack 明确更新会整目录替换二进制目录，资产会在升级时丢失。
- **全局「最新版本」指针**：多版本程序共用用户目录时会拿到不匹配的资产。
- **自动后台更新**：模型体积与流量成本高，且与「用户主动触发」的现状冲突，不在首版范围。
