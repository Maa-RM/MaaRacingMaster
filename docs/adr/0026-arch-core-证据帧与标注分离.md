# ADR-0026（arch-core）：证据帧与标注分离——落盘只写原始像素

- **状态**：`accepted`
- **日期**：2026-11-12
- **决策者**：用户（提出「peep 和模板居然都要从这里取图，但我又不希望原画面被遮挡」）
- **相关**：ADR-0021（会话优先取证布局）、ADR-0019（运行级统一）、[`core/CODE_WIKI.md`](../../maaracing_master/core/CODE_WIKI.md) §1.4 与 §5.1

## 背景

调试流只有一份帧：`_process` 里把采集帧画上状态文字、导航命中框、光标与点击意图，
然后**同一张图**被三个下游消费：

1. PEEP 实时预览（要标注，因为人要看「现在在哪一步」）；
2. 会话回放（`debug/<会话>/<模块>/<行为>/NNNNNN.jpg`，Studio 读它）；
3. 模板标定与裁剪（Studio 的 ROI 页也在读同一批图）。

第 3 项要求画面绝对干净，第 1 项要求画面必须有标注。两者被绑在同一张图上，
于是「干净」只能靠人肉规避：裁模板时自己躲开文字。这个约定在 2026-11-12 的赛季
公告页破了——状态行正好压在左上角返回按钮上，同一张模板画面从带字帧裁和从干净帧裁
是两个结果，前者会被判成废图。这不是操作失误，是**证据与视图共用了同一份存储**。

## 决策

一次帧处理拆成三件互不越界的东西：

1. **证据帧**：落盘的原始像素，`_process` 的 save 分支**不得有任何绘制调用**。
   模板标定、回放、训练素材都从它取。这是唯一进磁盘的像素。
2. **标注数据**：`_overlay_payload` 把状态解释成纯数据——归一化坐标（`nav_box`、
   `cursor.at`、`intent.at`）加文案槽位（`lines[].slot`/`text`），随帧写进
   `frames.jsonl` 的 `overlay` 字段。**解释只有这一处**，视图与回放共用同一份口径，
   不会出现「预览说这一步、索引说另一步」。
3. **视图帧**：`_render_overlay` 把同一份 payload 画在**副本**上，只喂 PEEP 编码，
   不落盘、不进索引。

坐标一律归一化：帧分辨率是外部输入，写死像素在换分辨率时整体错位，而归一化与
pipeline 里 ROI 的 JSON 口径一致。

标注**不进文件头**（JPEG COM 段）：那要重编码或改写字节，多一条失败路径，
且消费方还得先解容器；JSONL 一行一帧、追加即写、崩溃可读，与现有索引同构。

## 后果

**收益**：

- 从任何会话帧裁模板都不会带字幕，这类问题从结构上消失，不再依赖「裁的时候注意点」。
- 回放的状态文字改由 Studio 的 canvas 画（`overlay` 字段），可以随时关掉看干净图。
- 模块渲染器（`install_renderer`）从落盘通路移除，只作用于 PEEP 视图：它炸了只丢
  这一拍的预览（`peep_render_failed`），证据照样落盘——从前它会连带丢掉一帧图。
- 标注变成可机读数据：按帧检索「哪一帧命中了哪个模板」不再需要 OCR 图上的字。

**代价与约束**：

- 落盘帧与「看到的画面」不再长得一样，排查时要在 Studio 里开标注层（默认开）。
- `_process` 的 save 分支加任何 `cv2.putText` / `rectangle` 都是回归，测试
  `tests/test_debug_frame_evidence.py` 会红：它比像素差，也检查底部黑带没有落到磁盘。
- 旧会话的帧是带绘制的，且没有 `overlay` 字段——Studio 据此判断并提示「旧版落盘，
  裁模板请换新会话」，不假装历史数据是干净的。
- 遗留入口 `save_frame` 仍会绘制落盘，只服务归档模块；新代码不得接入。

**被否方案**：

- **落两份（`raw/` 与 `annotated/`）**：存储翻倍，且消费方仍要选，选举点从「画不画」
  变成「读哪份」，没有解决分歧，只是把它挪了个位置。
- **只在裁模板时避开文字**：把结构问题降级成操作纪律，下一个新面板、换一次字号就复发。
- **加高画布，把状态栏放到画面下方**：帧尺寸一变，ROI 归一化、回放、既有标定全部错位；
  直接分离像素与标注，比挪地方便宜得多。
